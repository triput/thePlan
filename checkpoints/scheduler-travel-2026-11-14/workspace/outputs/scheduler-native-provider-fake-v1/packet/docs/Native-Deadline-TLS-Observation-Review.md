# Native deadline, disconnect and TLS observation review

Dex, November 12, 2026. Static production-source review only. Source-Pins-Native-Observation-Review.json contains six exact raw hashes. No execution or PASS claim.

## What the fixture needs to distinguish

1. Actual request clock: CoveringRequestBudget captures request start once, with work deadline +210s and request deadline +240s. A case-local elapsed clock is not interchangeable with the ASGI admission start. Record both admission and fault-stage times, then classify the application's own result before any outer supervisor termination. Reaching a supervisor timeout is STOP, not proof of application expiry.
2. Shared cleanup: cleanup() sets the smaller of the remaining absolute request deadline and remaining cumulative cleanup allocation. It subtracts elapsed time across serialized cleanup scopes; it does not promise a fresh30s after each role or after an already-expired240s request. A separately declared fixture-worker retirement cap does not extend the product deadline.
3. Default production chain: CoveringReleasePlan.for_request constructs ProviderCounter(approved_provider_limits(), budget.work_remaining) and CoveringHTTP without an injected transport factory. That default carries the live work/cancellation callback into JoinedTLS. A fixture must preserve that chain for a default-transport claim.
4. Handshake/header/body stalls: JoinedTLS.check checks ownership/closed state and calls the live remaining callback. ready() polls for at most min(remaining,0.05), then checks again after readiness. open/handshake, send and receive have phase-specific checks. Record actual entry into the selected stalled phase and the first resulting application exception/classification; an open socket alone does not prove that the TLS handshake or HTTP header/body stage was reached.
5. Partial send and uncertainty: JoinedTLS marks sent=True BEFORE invoking the socket send, conservatively allowing a failure after accepted bytes. It is an uncertainty latch, not an exact sent-byte counter. A peer receiving only a prefix does not by itself prove the sender failed before finishing its own buffer. Do not present that as a measured partial-send witness. Disclose exact stimulus/observability and retain the no-replay/result oracle. Production instrumentation changes are outside the approved assembly-only boundary.
6. TLS EOF: wrap_socket uses suppress_ragged_eofs=False, do_handshake_on_connect=False, CERT_REQUIRED and check_hostname=True. close() is a local socket close; it does not unwrap or perform an extra TLS exchange. The peer must separately establish orderly close_notify versus abrupt stream closure. Complete self-delimited responses need no invented trailing EOF read. Positive close-delimited support and orderly short-Content-Length refusal require separate observations even if grouped in one STOP unit.
7. Actual ASGI disconnect: middleware receives http.disconnect and sets the cancellation event used by the budget. dispatch shields the AnyIO worker and uses abandon_on_cancel=False. Provider EOF, asyncio-task cancellation and injected http.disconnect are three distinct stimuli. The native observation must show the actual selected ASGI signal and worker completion/retirement; an empty provider receive is not a substitute.
8. Ownership/reuse: foreign check and foreign close have explicit get_ident guards. close marks closed before local socket close and is idempotent for the owner. open refuses an already-owned socket before starting another connection. Check each claimed native ownership oracle immediately; a combined case name alone cannot establish them.

## Application outcomes versus fixture STOP

CoveringHTTP remaps post-send OAuth failures to application UNKNOWN, preserving no-replay behavior. That may be an expected case observation when exactly declared. A failed fixture assertion, unjoined worker, invalid diagnostic, supervisor timeout, hash mismatch or unknown fixture resource disposition remains a framework STOP; never relabel it as an expected application UNKNOWN.
