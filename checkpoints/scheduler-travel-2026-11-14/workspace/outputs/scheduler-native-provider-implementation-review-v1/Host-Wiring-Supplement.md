# Supplemental host-wiring review — native preparation v1

Dex static review, November12. Same approved16-role authoring scope; no invocation or new permission.

1. **Inherited DockerOps.run_attached is suite-specific.** The immutable docker_transport.py copy starts the DB gate_pair.py, waits for gates_ready.py and requires exactly N06/N07 terminal receipts. That is appropriate to the prior native suite, not a transparent generic attach operation for NP-* provider batches. Do not carry that protocol into every new provider case or silently claim it is absent. In the already named mutable np_supervisor.py, bind/adapt the host operations deliberately (composition/subclass or equivalent), retaining unchanged helper bytes, command capture, exact identity and output/retirement guards. If a batch intentionally reuses the old gate protocol, declare it and account for it; otherwise use the needed attach/report operation without undeclared N06/N07 assumptions. Never modify the immutable helper copy or add a new mutable role without an applicable scope decision.

2. **Operator currently cannot dispatch the suite.** Invoke-Native-Provider.ps1 executes np_supervisor.py with no config/receipt arguments; the supervisor __main__ unconditionally exits HELD and never constructs Plan/DockerOps or invokes run_once. Implement the actual host command/config/evidence binding in the named roles under preparation authority. Invocation remains held. Native config files may remain launch_ready=false until reviewed, but the implementation must support the future admitted path.

3. **Configuration raw self-hash cannot be its own external admission.** Invoke-Native-Provider.ps1 reads expectedConfig from configObj.self_sha256 and compares it to the raw bytes hash of that same JSON. No excluded/zero-field preimage rule is applied at this comparison. This asks for a cryptographic self-hash fixed point, rather than a normally constructible reviewed packet. Put the expected raw configuration hash in an independently reviewed operator input/constant, as the prior packet does, and keep the exact command externally pinned. If a preimage field is retained for document identity, label and verify that rule separately; do not compare it as the raw hash. Use no dynamic hash-whatever-is-present launch command.

These are concrete implementation/wiring issues, not reasons to expand the goal or add a new preparation card. Carry them into the same fresh successor as R1–R4. Preserve frozen v1; final packet remains subject to independent review and explicit launch authorization.
