## Why the pin exists

Household DB is stamped **`042_task_occurrence_dispositions`**. Disposable-only **`043_recovery_epoch`** must not run on household. The API image `Dockerfile` default CMD is:

```text
alembic upgrade head && uvicorn …
```

`upgrade head` would chase 043 if that revision is present in the image. Until 043 is unlocked for household, every **api** create/recreate must override CMD to stop at 042.

## Restart vs recreate (correction)

| Action | Pin / CMD behavior |
| --- | --- |
| `docker restart compose-api-1` / Compose `restart api` | **Keeps** the existing container command. If the running container was created with the 042 override, a plain restart **retains** the pin. |
| `up --force-recreate` / `up --build` **without** the override file | **Replaces** the container from image/config defaults → Dockerfile `alembic upgrade head` returns. **This** is the landmine, not restart. |

Earlier rebuild Slack copy that said “a plain restart will try `upgrade head`” was **wrong**. Corrected here.

## Scheduler hold — mechanism (procedural)

**Not an enforced kill-switch in the worker.** The Compose `scheduler` service runs `python -m app.scheduler.worker --poll`, claims `schedule_runs` / running previews with `status=running` and `finished_at` null via Postgres advisory locks, and executes `run_replan` / `run_preview`. There is no hold env flag; `SCHEDULE_POLL_SECONDS` only sets poll interval.

**What “hold” means today:** operator / Cabinet procedure — do not admit new replans/previews (no `POST /schedule/replan`, no preview start that the worker would execute), no schedule unlock, no Track-1 replan work. The running worker **can** claim and execute if a runnable row appears.
