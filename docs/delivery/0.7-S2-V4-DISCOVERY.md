## 1. Goal (V4 only)

Make the **scheduler** treat **converted / assigned new rules** as scheduling-effective under the approved **May / Must / Prefer** composition model: **May** alternatives **union**; **Must** requirements **intersect**; **Prefer** **ranks only** among otherwise eligible candidates. **Prefer never creates availability** and never waives a requirement. Resolve **authorized scoped exceptions** into effective inputs **before** evaluating the eligibility stack (SPEC §4.2 / §4.4).

**Ship** the full V4 activation surface that **V3 left explicitly inactive**: schema + owner-scoped assignment operations + API/CLI + resolver + provenance/explanation (§2 IN, §14). Saved Personal policy rows are **not** assignments. Finish **same-level** legacy/new assignment **collision** (**V4-P1**) plus **clear / revert** (**V4-P2**) per [cutover §4.1 remainder](0.7-S2-CUTOVER.md#41-mixed-inheritance-resolution--provenance-s2-p2--settle-before-v3-coding) — product rules **locked Trish 2026-10-13**; Dex Q1 re-ack still required before coding.

**Legacy unconverted** Time Maps keep documented meaning (map ∩ Working after V3); **no** silent May/Must composition onto unconverted maps. S2-V4 is **engine composition / activation**, not Settings chrome (**S3**).

## 5. Composition contract (restated from authority — not new product)

From SPEC §4.2 / Dex redesign review / S0 — already approved language; V4 implements it for **activated** new rules:

1. Resolve assignments, origins, dates, weekday scope, and **scoped exceptions** first.
2. Determine declared eligible availability (May union among alternatives).
3. Intersect Must requirements; subtract exclusions / busy / hard constraints.
4. Rank remaining candidates with Prefer (rank-only).
5. If none remain, explain — never silently relax a requirement.

### 12.1 Where May / Must / Prefer composition would land

There is no scheduling-ref table and no `GET/PATCH /tasks/{id}/scheduling` writer. S0 §8 sketched that path for May-union policy refs. It is not in the router. `tasks.source_refs` is handoff URL provenance (`template_apply` / `outline_to_handoff`), not a scheduling assignment. Do not reuse it.

`AvailabilityPolicySlug` is only `general`, `work`, `personal` (`models/enums.py`). Policies live on `availability_policies` / `availability_windows` (`models/availability.py`). They are owner schedules, not per-task May/Must/Prefer links.

| Step | Where | What it does today |
| --- | --- | --- |
| Legacy inheritance | `scheduler/windows.py` `effective_preferred_time_window_id` / `effective_preferred_time_window_source` | Task `preferred_time_window_id`, else project, else epic, else `None`. Focus-window UUID only. |
| Collect | `scheduler/collect.py` `collect_inputs` | Writes `effective_window_by_task` from that function. Loads Working + General via `load_owner_policy_windows`. Does not load Personal. |
| Call | `scheduler/calculate.py` `place_one_block(..., preferred_window_id=inputs.effective_window_by_task[task_id], working_windows=..., general_windows=...)` | Resolved id, not a second lookup. |
| Search choice | `placement._day_search_windows` | `general_windows` when `preferred is None`; `working_windows` when a map is bound. |
| Clip | `placement._search_windows_for_day` | `materialize_windows_for_local_date`. No spans → `[]`. Unclassified (no map, no `day_bands`) → merged spans, tier `None`. Mapped → override split + `_windows_from_bands` (green / yellow / neutral, red subtracted). |
| Rank (legacy tiers) | `placement._merge_tier_windows` then `place_task` | Order is green, yellow, neutral, `None`. `find_slot` takes the first fit on that day. This is Time Map band tier, not Prefer. |
| Explanation tier | `scheduler/reasons.py` (placed text can say `in {tier} tier`); `calculate.py` copies `block.tier` | No unmet-preference reason code. A14’s explained unmet preference has no symbol. |
| Materializer | `scheduler/availability_materializer.py` | `load_owner_policy_windows` copies **work** and **general** only (“Personal is not eligibility”). `materialize_windows_for_local_date` / `merge_utc_intervals` / `occurrence_span` own overnight tails on the start weekday. Multiple windows on **one** policy already merge. That is not a May union across policies and not a Must intersection. |
| Effective read | `services/task_scheduling_effective.py` `build_task_scheduling_effective` | Same inheritance helpers. Sources in `_build_sources`. Policy rows via `_saved_policy_out`. |
| Policy HTTP | `api/routes/availability_policies.py` `_policy_out` / `_note_for_slug` | `scheduling_effective` true only for `work` and `general` (`policy_scheduling_effective_for_slug`). |
| Wrong clip helper | `services/availability_policies.py` `effective_windows_for_date` | Filters `window.weekday == on.weekday()`. Provenance says the placer uses the materializer. It does not emit an overnight tail onto the next calendar date. Composition must not use it as the placer clip. |

`place_task` falls back to `task.preferred_time_window_id` only when the caller omits `preferred_window_id`. Calculate does not omit it.

**Where V4 composition would attach (not a product lock):**

- **Assignment resolution** cannot be stuffed into `effective_preferred_time_window_id`. That function returns a `focus_windows` id or `None`. `None` already means unclassified → General after V3. S0 and cutover §4.1 forbid storing a General/purpose link in `preferred_time_window_id`. **Suspect:** a sibling resolver next to `windows.py`, called from `collect_inputs` and `build_task_scheduling_effective`, because those are the two readers of the task → project → epic chain. No such function exists.
- **May union / Must intersect** sit after that resolution and before `find_slot`, in `_day_search_windows` / `_search_windows_for_day`, feeding `materialize_windows_for_local_date`. Personal rows are stored and then dropped in `load_owner_policy_windows`. Scoped exceptions (SPEC §4.4, resolve before the stack) have **no table and no resolver**. **Suspect** they would be an input to that same search helper. Day-scoped replacement vs exclusive is **V4b** (A14b). `time_map_overrides` is legacy day replacement on a map, not that operation.
- **Prefer rank-only** sits after eligible spans exist: the `place_task` window walk, or a rank step in front of `find_slot`, plus an explanation fact beside the tier text in `reasons.py` / `calculate.py`. Do not treat green/yellow/neutral as May/Must/Prefer. Prefer must not call the materializer as a span source. Today an empty policy materializes to `[]` and the day contributes nothing; that shape is why Prefer-without-May must not be implemented as “load another policy into `policy_windows`.”
- **Legacy unconverted maps stay on the mapped branch:** bound `FocusWindow` → bands ∩ Working. No May/Must composition on that branch.

If malformed/imported data contains both families active at the same scope, surface a repairable conflict rather than picking an arbitrary winner.

2. **Clear and revert are different, revision-checked operations.** Clear removes the current local assignment and re-resolves current inheritance; it does not secretly restore a displaced local map. Revert explicitly restores the prior local assignment state captured by the replacement operation (including “no local assignment,” if that was the prior state). It does not rewind parent settings or shared policy hours. Require the expected revision/current assignment so a stale retry cannot undo somebody else's intervening edit. If a referenced prior map/policy was removed or is no longer usable, reject with a repair choice instead of falling back silently.
