## 0. S1→S2 compatibility bridge — what is usable when

S1 may add nullable bounds, progress columns, and availability/config tables while the **placer** still uses legacy reads for most eligibility until S2. That intermediate state must not lie about what is “effective.”

### 0.1 Bounds: compatibility resolver (chosen)

Placement today reads task `max_block_duration_minutes` (and min) as numbers. After `028`, NULL means inherit.

**Decision:** ship an **effective-bounds resolver** used by placer and by API `effective_chunking` — do **not** leave NULL in the placer path, and do **not** freeze all new bound writes until S2.

| Stored | Resolved for placer / validation |
|--------|----------------------------------|
| Explicit minutes | That number |
| NULL min or max | Corresponding user default |
| `max_block_unbounded` / user unbounded | No finite max (placer treats as unbounded; remaining + windows still cap) |
| `keep_in_one_block` | Passed through; S2 placer enforces fully; S1 may validate only |

**Usable in S1:** set/clear inherit (NULL), explicit No limit, user default max — writes persist; reads show effective + source. Placer always sees resolved numbers via the resolver.

### 0.2 Effort for placement during dual-read

After progress columns exist, ordinary re-estimates update **remaining**, not original (§1.1). Therefore the S1 placer **must** take placement effort from `remaining_minutes` (fallback: `estimated_duration_minutes` only if remaining is null mid-deploy). This is a **read shim**, not the full S2 pin-reservation cutover.

| Placer input | S1 (bridge) | S2 (cutover) |
|--------------|-------------|--------------|
| Effort to place | `remaining_minutes` | `remaining_minutes` |
| Pin reservation | Legacy: subtract **all** pinned minutes from that effort | Future-tail only (§2) |
| Eligibility windows | Legacy `workweek_*` + Time Maps | Working clip + General / May–Must composition |

### 0.3 General / Working — config vs scheduling-effective

Editable General (and Working/Personal) may ship in S1 for seed, read-back, and settings UX, but **must not be presented as scheduling-effective** while the placer still ignores them.

| Surface | S1 intermediate | S2+ |
|---------|-----------------|-----|
| `GET` policies / seed | Yes | Yes |
| `PATCH` General / Working / Personal | Yes — **config only** | Yes — scheduling-effective |
| API/UI label | `scheduling_effective: false` (or equivalent); copy: “Saved for upcoming scheduling; current runs still use working hours / Time Maps” | `scheduling_effective: true` |
| `GET …/effective` for policies | Config resolution + provenance OK; must **not** imply placer used it | Placer + explanations use it |
| Unclassified eligibility | Still today’s global `workweek_*` window | General |
| Mapped tasks | Legacy map + Working-as-global-bound via `workweek_*` mirrors | Map clipped to Working policy |

Round-trip: while Working is still a single Mon-first same-hours pattern, writes to Working may update deprecated `workweek_*` mirrors so legacy placer stays coherent. Once Working cannot round-trip, Working is SoT and S2 cutover is required before claiming effectiveness.

## 1. Progress init — do not infer past work

**Semantics** (SPEC §5.1; Dex “Track distinct quantities”):

| Field | Meaning | Drives placement? |
|-------|---------|-------------------|
| Original | Retained initial estimate | No |
| Worked | Explicitly logged effort only | No (stales previews; does not place) |
| Remaining | Current unfinished estimate | Yes — via S1 read shim (§0.2); full pin-reservation rules at S2 (§2) |

**Reuse** `tasks.estimated_duration_minutes` as **original**. Do not rename in `028`.

**Add** `tasks.worked_minutes` and `tasks.remaining_minutes` (`>= 0`). Zero remaining is valid. New worked entries must be positive minutes.

**Seed every existing task** (including completed and trashed):

- `worked_minutes = 0` — **never** sum `scheduled_blocks`, pin duration, or elapsed wall time.
- Open tasks: `remaining_minutes = estimated_duration_minutes`.
- Completed (`is_completed`): `remaining_minutes = 0`; still `worked_minutes = 0`. Completion is the lifecycle flag, not a backfilled log.
- No effort-history rows at seed. History starts at the first explicit entry or correction.

**Create (new tasks):** original = remaining = saved estimate; worked = 0.

### 1.1 Protect original estimate (post-migration, including before S2)

`estimated_duration_minutes` is the **retained original** after migrate. Older UI / API / CLI paths that PATCH “estimate” / `estimated_duration_minutes` must **not** overwrite that history on ordinary re-estimation.

| Client action | Post-migration server behavior |
|---------------|--------------------------------|
| Ordinary estimate edit (legacy field or “duration” control) | Update **`remaining_minutes` only**. Leave `estimated_duration_minutes` (original) unchanged. |
| Remaining-only re-estimate | Update `remaining_minutes` only. No worked row. |
| Atomic progress log (§1.2) | Append worked; set confirmed remaining; never rewrite original. |
| Explicit original correction | **Out of ordinary path.** Only via a dedicated correction op (if/when shipped) with clear copy that history changes; default product: ordinary edits never change original. |
| New task create | Set original = remaining = estimate as today. |

API read-back exposes `original_estimate_minutes` (alias of `estimated_duration_minutes`), `time_worked_minutes`, `remaining_estimate_minutes` so new clients stop treating original as the editable estimate. Legacy field name may still appear on wire for compat, but write semantics follow the table above from the moment progress columns exist.

Missed sessions and elapsed blocks do not reduce remaining. Unrelated edits do not reconvert stored minutes (SPEC §5 nominal-workday rule). Completion does not invent a log row or rewrite original/worked; remaining 0 **offers** completion; logging does **not** set completed.

### 1.2 Atomic progress log (approved write shape)

**Do not** split “idempotent log” and “confirm remaining via PATCH” into two commits — log-succeeds / remaining-fails is unacceptable.

**Approved progress action:** one atomic, retry-safe operation that, in a single transaction:

1. Appends (or idempotently replays) the worked entry, and  
2. Persists the **confirmed** remaining the user accepted, and  
3. Applies stale-state protection (`expected` task/progress revision or equivalent; reject stale → refresh), and  
4. Returns a receipt (same key + same intent replays; key reuse with different intent conflicts).

Suggested shape: `POST /tasks/{id}/progress-entries` body `{ idempotency_key, minutes_worked, remaining_minutes, expected_revision?, note? }` — suggestion UX may still compute a default remaining client-side, but **commit is one call**.

**Remaining-only re-estimate** stays a **separate** op (PATCH remaining or dedicated remaining endpoint) — no worked row, still must not touch original, still stale-protects and stales previews.

**Dual-read note:** Migration itself does not insert, move, or delete blocks (SS-01). API copy must not claim full S2 pin-reservation semantics during the S1 bridge.

**Nominal workday** (separate): new `user_settings.nominal_workday_minutes` — existing accounts seed from `workday_minutes`; fresh accounts **480**. Not an availability fingerprint input; does not rewrite estimates.

## 2. In-progress pins — reserve remaining, no double-count

Today every pinned interval (past and future) is subtracted from estimate while also occupying the busy map.

**S2 reservation** (evaluated at the run’s `now`, not stored at migrate):

| Pin vs `now` | Reservation toward remaining | Worked |
|--------------|------------------------------|--------|
| `end <= now` (past) | 0 | unchanged |
| `start >= now` (future) | full duration | unchanged |
| `start < now < end` (in progress) | minutes from `now` to `end` only | unchanged |

The elapsed head is **not** worked and **not** reserved. Do not split the block row into past + future at migrate. Unpinned blocks reserve nothing and prove nothing.

**Excess pin vs remaining:** additional auto minutes = 0; surface mismatch on the task outcome. Do **not** shorten, move, unpin, or clamp remaining to the pin. User fixes via remaining edit, pin edit, or explicit log.

Busy-map occupancy stays the **full** pin interval so auto blocks cannot land on it. Prerequisite remaining uses the same future-tail rule. Sliding `now` does not itself stale a preview (`pins` stay absolute intervals).

**S1 bridge:** placer still subtracts **all** pinned minutes from placement effort (`remaining_minutes` per §0.2). S2 switches to future-tail reservation without double-count.

## 3. Legacy block min/max → defaults / inheritance

Today every task has non-null min (15) / max (120); settings have default min only.

**User defaults**

- Keep `default_min_block_duration_minutes` (15).
- Add `default_max_block_duration_minutes` seed **120**, and `default_max_block_unbounded` default **false**.
- User-level No limit = unbounded flag (not NULL, not 0).

**Task bounds**

- NULL min or max = inherit that bound (show effective value + source).
- Explicit minutes override only that bound.
- `max_block_unbounded = true` = explicit **No limit** (distinct from omission).
- `keep_in_one_block` default **false** — all **remaining** work in one continuous eligible window; do not infer from `max >= estimated`.
- Validate effective min/max together; conflict → correction error. Final remainder shorter than min stays legal. Buffers are not work duration.

**Seed:** leave existing task min/max as **explicit** stored integers. Do **not** collapse “equals 15/120” to NULL. Inheritance applies to new tasks and to bounds the user later clears.

**Placer:** always via §0.1 resolver during S1+.

## 4. Existing tasks / accounts — Working, General, Time Maps

Global eligibility today: `weekday() < workweek_days` + `workday_start_local` / `workday_minutes`. Time Map bands clip to that window. One map wins (task > project > epic) via `preferred_time_window_id` → `focus_windows`.

**Seed per owner (schedule timezone):**

| Policy | Seed |
|--------|------|
| **Working** | Days `0 .. workweek_days-1`, one window `[workday_start_local, start + workday_minutes)`. Overnight → explicit overnight on start day. `workweek_days = 0` → no Working days. |
| **General** | **Independent copy** of those same windows (not a live alias). Unclassified tasks **link** to General; do not copy hours onto each task. |
| **Personal** | Named policy with **zero windows**. Do **not** invent evenings or weekends. Empty ≠ unrestricted; not unioned into General. |
| **Context baseline** | Home + computer + phone (editable). Context does not create availability; seed does not move blocks. |
| **Fresh accounts** | Working **and** General = Mon–Fri 09:00–17:00; nominal workday 480. |

**Legacy Time Map until explicit conversion:** keep `preferred_time_window_id` on task/project/epic, `focus_windows` (strict, bands, red), `time_map_overrides`. Replacement inheritance stays; do **not** opt maps into May/Must composition in `028`.

**Eligibility preserve (SS-01) at seed / S2 cutover:**

- No map: General only (at S2). At seed, General equals today’s global window so cutover can match. During S1 intermediate, unclassified still uses `workweek_*` (§0.3).
- Legacy map still assigned: keep today’s map interpretation, clipped to **Working** (old global bound), not to General. Later General edits must not widen/shrink mapped tasks.
- Do not invent fall-through from empty strict map to General.

`workweek_days` / `workday_start_local` / `workday_minutes` remain deprecated mirrors through S1 while Working is still representable as that pattern. Do not drop columns in `028`. Strict/non-strict/red/empty/override conversion table remains a separate S1 acceptance input (SPEC §3, §12) — this packet forbids **implicit** conversion.

## 5. Fingerprint / revision categories to reserve

Fingerprint snapshot **v3** categories today include `duration`, `deadline`, `map_style`, `deps`, `pins`, `project_daily_cap`, `timezone_horizon_workweek`, `lifecycle`, `busy_external`, `prerequisite_state`, `due_at_soft_target`, `time_map_overrides`.

**Bump to v4 when the S2 placer driver ships** (not in the `028` data seed). Existing v3 rows then read as `provenance` (current rule). Do not rewrite historical explanation JSON in Alembic. **`028` must not bump `scheduling_revision`** — seeded policies match v3 inputs so in-flight previews stay valid until a real edit or the v4 cutover.

**Reserve these names; do not overload legacy ones:**

| Category | Covers | Does not cover |
|----------|--------|----------------|
| `availability` | Working / Personal / General windows; dated add/replace; purpose assignment that changes eligible windows | Legacy map id / strict / bands (`map_style`); overrides (`time_map_overrides`); nominal workday |
| `context` | Baseline, preset revision, declarations, resource/location timeline, explicit event-travel allowances | Availability windows (context stales suitability, does not grant schedule permission) |

**Adjust existing categories in v4 (same names):**

- `duration` also hashes original / worked / remaining, inherit vs explicit vs No limit, and keep-in-one (progress edits stale via this category — SS-26). No second progress category.
- `timezone_horizon_workweek` keeps timezone, horizon days, `inter_block_buffer_minutes`. Workday start/length/workweek move to `availability`.
- `pins` stays absolute intervals; reservation is derived (§2).
- `map_style` / `time_map_overrides` stay until conversion deletes that path.

Configuration apply remains a different transaction from schedule preview/apply (SPEC §7).

## 6. Buffer policy (SS-30) — pre-S1 answers + S2 evidence

Aligned with SPEC SS-30 and §12: **Pre-S1** settle intended **policy** and **test plan** (no circular wait on full evidence). **S2** run verification on the implemented scheduler and record results/defects. This section is **not** “closed because questions wait until S2.”

Not a schema change this packet. Reuse `user_settings.inter_block_buffer_minutes` (default 5).

**Code fact for verifiers:** initial busy map loads pins and external events at exact bounds (no padding); buffer applies as trailing padding on **newly placed** auto blocks today. That inspection is not evidence the boundary policy is correct (Dex v1.16) — S2 evidence must check the **approved** policy below against implementation.

### 6.1 Pre-S1 policy answers (proposed defaults — product-aligned)

Trish may object; until then these are the contract defaults for Renee’s test plan. None marked Outstanding unless noted.

| # | Question | Pre-S1 policy answer |
|---|----------|----------------------|
| 1 | Gap vs pins / external busy? | **Both sides of fixed busy when placing auto blocks:** an auto block must leave ≥ buffer clearance from pins and external busy (and from other auto blocks). Fixed items are never moved to manufacture a gap. |
| 2 | Split blocks of one task? | **Yes — buffer between consecutive auto blocks of the same task** (they are separate calendar intervals). |
| 3 | Travel allowance vs buffer? | Travel intervals are busy occupancy. **Do not double-charge** (no extra buffer *inside* an explicit travel allowance). Auto placement still owes normal buffer clearance **against** the travel busy interval, same as against a pin. |
| 4 | Is 0 legal? | **Yes** — buffer 0 means adjacency allowed, including against pins/events. |
| 5 | Tighter than buffer? | **Unscheduled + explanation**; pins and external events unmoved; buffer setting not silently dropped. |
| 6 | Order independence? | **Yes** — result must not depend on insertion or priority order for the buffer constraint itself. |
| 7 | Preview/apply + stale? | **Agree**; changing `inter_block_buffer_minutes` stales via existing buffer fingerprint input. |
| 8 | Fixed items already closer than buffer? | **Report conflict**; do not move them. |
| 9 | Out of remaining / bounds? | **Confirmed** — buffers are not part of remaining work and not part of block-size min/max (SPEC §5.1). |

**Outstanding for Trish before S1:** none under these defaults. If Trish wants one-sided buffer only between autos (current-code-shaped) instead of clearance against pins/external, that is the one product fork — object before S1 implementation locks the test plan.

### 6.2 Pre-S1 test plan (Renee) — not execution

- Cases at buffer **0 / 5 / 10**.
- Auto vs auto; auto vs pin; auto vs external busy; same-task split; travel allowance present; preview vs apply; order swap; pre-existing tight fixed pair.
- Record pass/fail + defects in SS-30 evidence at **S2** (execution gate). Do not treat this packet as that evidence record.

## 8. API shape sketch (Jules)

Base: `/api/v1`, owner-scoped, existing error/pagination patterns. Names are proposals; persistence may adjust if semantics hold.

| Group | Paths (proposed) | S1 note |
|-------|------------------|---------|
| Settings (extend) | `GET/PATCH /settings` | `nominal_workday_minutes`; default max / unbounded / keep-in-one defaults — **scheduling-effective** where they feed resolver / legacy workweek |
| Availability policies | `GET /availability-policies`, `GET/PATCH …/{id}` | Stable slugs `general` \| `work` \| `personal`; **config-only** until S2 (`scheduling_effective: false`) |
| Effective availability | `GET …/{id}/effective?on=YYYY-MM-DD` | Config resolution + provenance; must not imply placer used it in S1 |
| Task scheduling | `GET/PATCH /tasks/{id}/scheduling` | May-union policy refs; Must/Prefer stubs as needed; **legacy** `preferred_time_window_id` unchanged |
| Effective rules (read) | `GET /tasks/{id}/scheduling/effective` | Legacy map chain + policy config + `sources[]`; label what is placer-active vs pending |
| Progress | `TaskOut` + **atomic** `POST /tasks/{id}/progress-entries` | One txn: worked + confirmed remaining + stale check; remaining-only separate |
| Context (narrow) | `GET/PATCH /context/baseline` | Presets/declarations list stubs OK until later slices |
| Config propose/apply | `POST /scheduling/config/propose\|apply` | Mirror handoff pattern (SPEC §7); **not** first vertical |
| Unchanged | `/focus-windows`, overrides, `/schedule/*` | Legacy Time Maps + preview/explain — still the effective path in S1 |

**Migration-facing reads:** after migrate, `GET /availability-policies?slug=general` always succeeds; unclassified tasks expose `scheduling_provenance` for the **future** General link without claiming current placer use. Optional read-only `effective_scheduling_minutes` during dual-read.

**Legacy stability until conversion:** `/focus-windows` CRUD, strict mode, bands, override overlap rules, explanation stale `time_map_overrides`. No silent reinterpretation as additive rules. Opt-in conversion endpoint is later — not default S1 behavior.

## 10. Recommended first S1 slice

Smallest vertical that unblocks foundations without full S2 placer rewrite:

1. Alembic `028_*`: availability policy + window tables; seed Working / General / empty Personal; task progress columns; nominal workday; nullable task bounds + No limit / keep-in-one flags; settings default max — **no** block rewrites, **no** fingerprint JSON rewrite, **no** `scheduling_revision` bump.

3. Placement effort read shim → `remaining_minutes` (§0.2); legacy estimate PATCH → remaining only (§1.1).
4. Atomic progress endpoint (§1.2) + `TaskOut` progress/chunking fields.
5. `GET/PATCH` General (and read Working/Personal) + extended `/settings` — **config-only** flags (§0.3).
6. `GET /tasks/{id}/scheduling/effective` (provenance; distinguish placer-active vs pending).
7. Migration tests: SS-01 (no block moves), progress init (worked = 0), original protected on estimate PATCH, General/Working seed read-back, resolver cases.

**Explicitly out of first slice:** May/Must/Prefer in placer, future-tail pin reservation (S2), treating General as eligibility, config propose/apply, context declarations timeline, overnight/split policy UX, legacy map conversion endpoint, full CLI map CRUD, SS-30 **execution** evidence (policy+plan are pre-S1 in §6).
