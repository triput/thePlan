## 1. Goal / non-goals

### Goal

Produce **layered, reproducible evidence** that separates:

| Layer | Question |
| --- | --- |
| **A — In-container API** | Does the API process answer HTTP on `:8000` inside the api container? |
| **B — Service-to-service** | Can **web → api:8000** on `preg5_net` succeed (or equivalent mesh probe)? |
| **C — Publish / Docker binding** | Does Docker record `127.0.0.1:18000 → api:8000` on the engine that owns the project? |
| **D — Windows-host reachability** | Can **Windows** (PowerShell / runner host) open TCP and get HTTP from `127.0.0.1:18000`? |

Deliverable: a **bounded LIVE attempt** (`disposable-042-reach-1`) whose artifacts let Dex/Trish choose **Option B** (minimal network/isolation change), **Option C** (change validation probe surface, e.g. exec-only), or **root-cause elsewhere** — without conflating layers.

## 4. Layered probe matrix

**Convention:** **READ-ONLY** = safe with **no** disposable containers running. **LIVE** = authorized disposable stack through api/web running; probes before treating host V4 as authoritative.

**Capture rule (LIVE):** stdout+stderr under `{attemptDir}\reach-probes\` per §7. `reach-probe-session.json` records UTC bounds, **`docker context show`**, **`docker context inspect`** endpoint **Host**, **`DOCKER_HOST`**, **`DOCKER_CONTEXT`**, and engine version.

**PS 5.1 HTTP (host L1-J):** Do **not** use `-SkipHttpErrorCheck` (PS7-only). Use **`Assert-HttpJsonExpectation`** / **`WebException.Response`** pattern: expected **401 + body** is success; connection/timeout errors are **transport_fail** (separate from HTTP status mismatch).

**In-container HTTP (L1-F / L1-H):** **L1-F (api):** **`python -c` + `urllib`**. **L1-H-web:** try python first; pinned web image **`sha256:636901af…`** (nginx **1.27.5** / Alpine **14.2.0**, val-2 logs) has **no Python** in RootFS (read-only **`docker save`** layer list) but **`/usr/bin/curl`**, **`/usr/bin/wget`**, and **`bin/busybox`** — runner falls back to bounded **`curl --max-time 15`** in the **web** container with **body then trailing `STATUS <code>`** (curl `-w`); parser accepts **leading** (python) or **trailing** (curl) framing. Lifecycle **`compose up` / migrate** stays **fail-closed** (`Invoke-PreG5DockerControl`); **diagnostic `compose exec` / `compose run --rm --no-deps`** uses **`Invoke-PreG5DockerControlAllowFail`**. **Non-zero exit with partial `STATUS` line is not `http_ok`.**

**Layer B source identity:** **`L1-H-exec-web-to-api.txt`** is **web exec only** (python attempt + curl result when python **`missing_tool`**). If **both** are **`missing_tool`**, optional **`L1-H-mesh-run-api-fallback.txt`** records a **separate** `compose run --no-deps api` urllib attempt — **not** web→api proof; receipt sets **`layer_b_web_to_api_proven=false`**. Fallback does **not** overwrite the web artifact.

**Timeouts:** Matrix deadline (default 180s) with **per-probe clamp** to remaining time — exec/run, publish inspect, host TCP (`TcpClient`), host HTTP, bounded **netstat** job. **Cleanup** uses its **own** budget (`ComposeCleanupTimeoutMs`, default 180s), not the matrix clock.

| `reach-probe-matrix-summary.json` | probe id → classification → interpretable pass |
| `reach-diagnosis.receipt.json` | `probe_collection_completed`, `interpretable_diagnosis_ok`, `reachability_diagnosis_ok`, `layer_b_web_to_api_proven`, `layer_a_in_container_ok`; **no** `startup_validation_ok` |
| `owned-resources-before-cleanup.json` / `cleanup-outcome.final.json` | When compose ran |
| `compose.rendered.json` / `.yaml` | Same asserts as validation |

**Evidence semantics:** **`probe_collection_completed`** is **true only when the full mandatory matrix finishes** before deadline (partial/deadline paths stay **false**). **`interpretable_diagnosis_ok` / `reachability_diagnosis_ok`** additionally require **`cleanup_outcome.cleanup_ok`**, mandatory rows **L1-B / L1-F / L1-H-web / L1-I / L1-J** present, **L1-F `http_ok`**, **`layer_b_web_to_api_proven`**, no blocking exec instrumentation on **L1-F / L1-H-web**, and no **host probe instrumentation** (**`tcp_error`**, **`tcp_timeout`**, **`http_error`**, **`matrix_deadline`** on **L1-I/J**). **Host `transport_fail` / `tcp_fail`** and **`publish_ok` / `publish_missing`** are valid observations. **`publish_instrumentation`** covers **docker port/inspect failures, timeouts, or matrix budget exhaustion** — not evidence that publish is absent (contrast **`publish_missing`** when commands succeed and bindings are absent). Port failure may still yield **`publish_ok`** when **`NetworkSettings.Ports`** parse succeeds. **Publish inspect** and **L1-A ps** recompute **remaining matrix time before each docker call**; **cleanup** keeps an independent budget.
