## Goal

Make duration and effort inspectable and editable with correct conversion/provenance so Julie never confuses **original estimate**, **remaining**, and **legacy `estimated_duration_minutes`**, and so nominal-workday conversion is honest.

## IN

| Area | Expectation |
| --- | --- |
| **Labels / aliases** | Structured fields: `original_estimate_minutes`, `time_worked_minutes`, `remaining_estimate_minutes`. Document that `estimated_duration_minutes` on reads is the **original** alias (immutable under ordinary PATCH). Do not force original == remaining. |
| **Friendly parse (API + CLI)** | Accept `90m`, `1h 30m`, `1.5h` → minutes on create / remaining / progress / settings nominal where applicable. Bare number in a minutes-labeled field = minutes. Reject negatives; positive→zero rounding asks for ≥1 minute (SPEC). |
| **Nominal workday** | `nominal_workday_minutes` converts fractional workdays at **save** only; changing nominal later must **not** rewrite stored task estimates. Show conversion before save when input uses workdays. Distinct from `workday_minutes` (legacy placement). |
| **Bounds inheritance** | Task min/max: explicit vs inherit (NULL) vs No limit — **writes** of inherit/No limit/keep-in-one still **rejected** until S2 (`CHUNKING_CUTOVER_PENDING`). Reads may **preview** effective inherited defaults from user settings without persisting inherit. |
| **CLI parity** | Same parse + labels via settings / tasks create / remaining / progress; help text names `settings get` for revision and points at original vs remaining. |
| **Effective read** | Duration block already present — ensure labels match this contract (no “post-pin remaining” claim). |

## OUT

| Out | Why |

| Activating inherit / No limit / keep-in-one writes | S2 |
