## Dex bounce — Item 1 (STOP-FINDING → alignment)

### Concrete collision finding (not “no collision in fixtures”)

Schema `unique_external_event` is `(provider, external_event_id)`. Two trusted busy rows (Google + MS) **may share** the same bare provider string.

At `f938a2e`, `trust_blocking_signature` built a global `by_diagnostic_event_id` map keyed by bare `external_event_id` and **raised `RuntimeError` on any duplicate** — including two trusted non-blocking rows. Reproduced against disposable `:5433`:

- Owner with Google + MS accounts
- Both rows: `external_event_id='SAME-BARE-ID-COLLISION'`, trusted opaque / `provider_explicit`
- Call → `RuntimeError: … diagnostic event_id='SAME-BARE-ID-COLLISION' maps to multiple ExternalCalendarEvent rows …`
- Effect: **new sync outage** instead of reporting an empty trust signature (or scoped blockers)

Fixture retained as `test_boundary_b_cross_provider_same_bare_id_no_sync_outage`.

### Identity alignment chosen (narrow; no resolver broaden)

**Dex suggestion verified and implemented:** invoke `evaluate_busy_input_trust` **per row** with that row’s enrichment only.

| Choice | Rationale |
| --- | --- |
| Per-row evaluator | Bare-id enrichment key is unambiguous within a single-event call; production trust rules unchanged; no `policy_enrichment_by_event_id` / resolver broaden |
| Row UUID identity | Injective. Colon-joined `owner:account:calendar:event` is **not** injective when components may embed `:` |
| Equivalence | Evaluator has no cross-event trust state beyond diagnostic accumulation; signature membership is `(row_uuid, cause, start, end)` — same causes/bounds as a batch call over the same rows |

**Not chosen:** keep raising stop-finding on duplicate bare ids; silently last-wins enrichment; broaden collect/resolver keys.
