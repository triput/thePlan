### 1.3 Honesty gap (why review endpoint)

Current `POST …/recover` is the **only** HTTP that exercises successor computation, catch-up default remaining, C2 predicate, and rolled next-normal dates — and it **mutates**. Client-side RRULE / bounds-roll duplication is **out of contract**. Submit-mutation-to-discover is **out of contract**. Therefore REC-UI **depends** on a narrow read-only review API (proposed below) **before** the authorize POST.

## 2. Proposed API dependency — read-only recovery review

**Verdict:** **PROPOSED DEPENDENCY** (not landed). Lands in the same coding-unlock family as T2-REC-UI (or as a tiny prior API commit under that unlock) — **not** granted by this planning packet alone.

### 2.1 Shape (consistent with held disposition POSTs)

| | |
| --- | --- |
| **Method / path** | **`POST /api/v1/schedule/held-misses/{task_id}/recover/review`** |
| **Why POST not GET** | Body carries named episode + revision + authorize binding + optional successor choice / catch-up overrides (same family as leave/release/skip/recover). Avoid GET-with-body. |
| **Mutation** | **None** — no nested savepoint writes; no catch-up Task; no disposition change; no `scheduling_revision` bump; no progress epoch membership inserts |
| **Reuse** | Call the **same** accepted helpers used by `recover_held` for successor, catch-up default remaining, C2 predicate, and (read-only) projected rolled bounds — **do not** fork RRULE policy into the web client |
| **AuthZ** | Same owner + task ownership as recover |

**Not** `POST /schedule/previews`. **Not** calculate/replan. **Not** provider refresh.

### 2.2 Request (`RecoverHeldReviewIn` — illustrative)

Mirror authorize binding fields; review may omit exclusive successor choice until the operator picks one (server then reports `FIXED_PAST_REQUIRES_CHOICE` as a **review outcome**, not a mutation).

| Field | Required | Notes |
| --- | --- | --- |
| `disposition_id` | **yes** | Named episode only |
| `expected_revision` | **yes** | Stale → **409** (parity with recover; no silent continue) |
| `authorize_instant` | **yes** | Bound at review open / refresh — **UI-supplied from clock**, not free-typed by Trish (see §3.4) |
| `accept_past_ack` | no | Default false |
| `step_count` | no | Optional fixed extra steps |
| `abort` | no | If true, review may short-circuit as aborted intent (still no writes) |
| `catch_up_due_at` / `catch_up_start_no_earlier_at` / `catch_up_start_no_later_at` / `catch_up_deadline_at` | no | Operator-edited catch-up window for gate preview |
| `catch_up_remaining_minutes` | no | Override incl. **0**; omit → server default |

Same exclusivity rule as `RecoverHeldIn`: at most one of `accept_past_ack` / `step_count` / `abort`.

### 2.3 Response (`RecoverHeldReviewOut` — operator review pane)

All fields below are **required for the UI contract** unless marked optional. Timestamps are timezone-aware instants; UI labels them in rule zone (see §3.4).

| Field | Purpose (Dex “MUST SEE before authorize”) |
| --- | --- |
| `disposition_id` / `task_id` / `episode_key` | Named episode identity |
| `expected_revision` (echo) | Binding shown / resent at authorize |
| `authorize_instant` (echo) | Bound review instant — **must** match authorize POST |
| `cadence` | `{ "is_fixed": bool, "timezone": "<IANA>", "rrule_summary"?: string }` — zone + fixed vs completion-anchored |
| `eligibility` | `{ "recurring": bool, "one_off_use_release": bool }` — non-recurring → reject recovery / steer to release |
| `next_normal` | Computed target: `due_at`, projected `start_no_earlier_at` / `start_no_later_at` / `deadline_at` (nulls preserved), `landing_is_past`, `accept_past_required` |
| `next_normal_effort` | `{ "worked_minutes": 0, "remaining_minutes": <estimate> }` — full next-normal restart |
| `catch_up` | Defaults + gated projection: `remaining_minutes_default`, `remaining_minutes` (after override if any), `due_at` / bounds / deadline as supplied or null, `usable_dates_ok` / reject code if catch-up window invalid |
| `historical_work` | Miss-era treatment: `worked_minutes`, `remaining_minutes`, `estimated_duration_minutes`, `ledger_retained_on_series`: true, `progress_entry_count` (or id-set length) — **no** duplicate onto catch-up |
| `c2` | `{ "blocks_prevent_next_normal": bool, "code": "BLOCKS_PREVENT_NEXT_NORMAL" \| null, "detail": "…" }` — limitation honesty; **no** remediation instructions to delete/unpin |
| `successor_choice` | `{ "status": "ok" \| "FIXED_PAST_REQUIRES_CHOICE" \| "RECURRENCE_NO_SUCCESSOR" \| "RECOVERY_REQUIRES_RECURRING" \| …, "accept_past_applied_if_authorized": bool }` |
| `review_ok_for_authorize` | bool — true only when authorize with **this** binding would pass gates known at review (C2 clean, successor resolved or explicit choice present, catch-up dates ok). False → UI disables Authorize and shows code |

**Errors (HTTP):** **404** missing disposition/task; **409** stale revision / `CONFLICT_TERMINAL`; **422** with existing codes where review can diagnose without write (`RECOVERY_REQUIRES_RECURRING`, `RECURRENCE_NO_SUCCESSOR`, `BOUNDS_ROLL_INDETERMINATE_LOCAL`, `BOUNDS_STILL_MISSED`, `FIXED_PAST_REQUIRES_CHOICE` as structured outcome preferred over hard 422 when choice is still available).

### 2.4 Authorize revalidation (POST `…/recover`)

Unchanged accepted mutate path. UI contract adds:

1. Authorize body **must** resend the **same** `authorize_instant`, `disposition_id`, `expected_revision`, successor choice, catch-up fields the operator reviewed.
2. Server **recomputes** under lock + revision assert (already in `recover_held`). If successor / rolled target / C2 / gates disagree with the reviewed binding → **reject** (409/422) — **no** silent shift to a new next-normal.
3. **409:** no auto-retry; single in-flight request; show conflict; refresh review.
4. Idempotent already-recovered same `disposition_id` → **200** with existing `catch_up_task_id` — UI treats as success (toast + link), not a second create.

## 3. UI contract

### 3.1 Screens / entry (no new shell)

| Place | Behavior |
| --- | --- |
| **CalendarSupportIdle** | Unchanged list; open task → detail. Optional quiet affordance only if Dex wants “Recover available” copy — **default:** no new idle action; recover lives on banner |
| **TaskDetailScheduling held banner** | For **recurring** + `unresolved_held`: add **Recover…** control beside leave / skip / release. One-off held → **no** Recover (release remains) |
| **Recover review pane** | Modal / inline panel on the banner — **not** Schedule Preview panel; **not** replan Calculate/Apply |

### 3.2 Fields — operator MUST SEE before Authorize

Rendered from **`recover/review`** (authoritative), not inventing client RRULE:

1. **Next-normal target** — due + projected bounds/deadline in **rule timezone** with zone label  
2. **Cadence / zone** — fixed vs completion-anchored; IANA zone string; DST honesty via labeled local walls  
3. **Full next-normal effort** — worked **0** / remaining **estimate**  
4. **Catch-up** — remaining default (incl. **0** when live remaining is 0); editable remaining; date/bounds inputs (local-time widgets, not raw UTC type-in)  
5. **Historical-work treatment** — miss-era worked/remaining/estimate retained on series ledger; catch-up starts clean; no duplicate of logged minutes  
6. **C2 limitation** — if `blocks_prevent_next_normal`: clear reject copy that recovery **cannot** proceed while same-task blocks/pins poison next-normal; **do not** offer or imply delete/unpin / “manual clear blocks” as the supported C2 remedy for this slice  

Authorize button enabled only when `review_ok_for_authorize` **and** (if `accept_past_required`) operator completed an explicit choice (accept past / step / abort).

### 3.3 Gates & actions

| Action | Contract |
| --- | --- |
| **Open Recover** | Fetch settings rev + named held row; call **`recover/review`** with UI-bound `authorize_instant`; show pane |
| **Refresh review** | Re-bind `authorize_instant` to “now” **only** on explicit refresh/re-open (operator understands target may change); never silently on idle timer mid-pane without notice |
| **Fixed past** | Require **Accept past** **or** **Step further (N)** **or** **Abort** — no silent auto-loop |
| **Accept past** | Explicit ack copy: may immediately need-decision again on past landing (visible honesty; not a bug) |
| **Abort** | Close pane; **no** recover POST |
| **Catch-up remaining** | Default from review; override allowed including **0**; never auto-fill historical worked as catch-up worked |
| **Authorize** | Single `POST …/recover` with reviewed binding; disable controls while pending; **no** 409 auto-retry |
| **Success** | Toast; show **catch-up task link**; `invalidateAfterHeldMutation` (+ `["task", seriesId]`, `["task", catchUpId]`); held list drops recovered episode; series detail refresh |
| **Idempotent success** | Same disposition already recovered → success UX with existing catch-up link |
| **Leave / skip / release** | Unchanged; Recover does **not** save unrelated task-title/notes/duration edits — only catch-up + successor fields in the recover request. Date-first release path remains separate (do not piggyback dirty unrelated draft fields into recover) |

### 3.4 Authorize instant — no technical type-in

- UI obtains `authorize_instant` from the **browser/app clock at review compute** (timezone-aware instant), displays it as **human local time + zone label**.  
- **Forbidden:** a free-text ISO / epoch field for Trish to type as the recovery control.  
- Operator may **refresh review** (re-bind) deliberately; authorize must send the **displayed** bound instant.

### 3.5 Local-time / DST labels

Parity with T2-S2-UI date-first release: use existing local-time inputs + `formatInstantInZone` (or equivalent) against **`RecurrenceRule.timezone`** (and app display zone labels). Ambiguous/gap walls: surface server `BOUNDS_ROLL_INDETERMINATE_LOCAL` — no client snap.

### 3.6 Errors (surface codes; no silent success)

| Code / class | UI |
| --- | --- |
| `FIXED_PAST_REQUIRES_CHOICE` | Show choice controls; disable Authorize until chosen |
| `BLOCKS_PREVENT_NEXT_NORMAL` | Fail-closed copy; **no** delete/unpin workaround CTA |
| `RECOVERY_REQUIRES_RECURRING` | Hide/disable Recover; point to release |
| `RECURRENCE_NO_SUCCESSOR` | Explain exhausted series; leave/skip/release remain |
| `BOUNDS_STILL_MISSED` / catch-up gate | Fix catch-up dates or abort |
| `BOUNDS_ROLL_INDETERMINATE_LOCAL` | DST gap/fold diagnostic; no authorize |
| **409** revision / `CONFLICT_TERMINAL` | Alert; invalidate settings + held; **no** auto-retry; retain operator catch-up edits in the pane |
| Network / 5xx | Alert; pane retained |

### 3.7 Caches

After successful recover (and on 409 refresh paths as today):

- Reuse `invalidateAfterHeldMutation`  
- Also invalidate **`["task", taskId]`** (series) and **`["task", catch_up_task_id]`** when known  
- Do **not** treat held-list fetch failure as empty  
- Do **not** trigger Schedule Preview create/apply or provider calendar refresh as part of recover success

### 3.8 Explicit anti-patterns

| Forbidden | Why |
| --- | --- |
| Client RRULE / next-due computation | Drift from accepted recovery-path helpers |
| Mutate-to-discover (POST recover as “preview”) | Violates MUST-SEE-before-authorize |
| Using Schedule Preview / Calculate / Apply / provider refresh as recovery review | Wrong abstraction; standing safe-usable holds |
| Typing arbitrary authorize timestamp | Dex: no technical field for Trish |
| Delete/unpin / “manual clear blocks” as C2 remedy in UI copy or flows | Current slice **rejects**; isolation **EXCEEDS_SLICE** |
| Auto-retry on 409 | Race / overwrite risk |
| Saving unrelated task draft fields on Authorize | Accidental PATCH scope creep |
| Household **043** / production acceptance in this slice | Explicit non-claim |
