### 1.3 Honesty gap (why review + binding)

Current `POST …/recover` is the **only** HTTP that exercises successor computation, catch-up default remaining, C2 predicate, and rolled next-normal dates — and it **mutates**. Client-side RRULE / bounds-roll duplication is **out of contract**. Submit-mutation-to-discover is **out of contract**. UI-echo of an operator/browser `authorize_instant` **cannot** prove the authorize body still matches the **displayed** review projection. Therefore REC-UI **depends** on (a) a **true read-only** review API and (b) a **server-verifiable** review↔authorize binding **before** the authorize POST.

### 1.4 Recurrence eligibility / zone — authoritative source (do not guess)

| Source today | Carries rule zone / `is_fixed` / recurring eligibility? |
| --- | --- |
| `GET …/held-misses` → `HeldDispositionOut` | **No** — identity + `bounds_snapshot` + miss reason only |
| `TaskOut.recurrence` (`RecurrenceOut`) | **Yes when present** — `rrule`, `is_fixed`, `timezone` (IANA), `display` |
| Some list / partial task payloads | Recurrence may be **absent / null** — **do not** invent from settings timezone or browser zone |
| Settings `timezone` / banner display zone | **Display convenience only** — **not** recovery cadence authority |

**Contract:** Review response **`cadence` + `eligibility`** (and any rule-zone label used beside targets) are **authoritative**, computed server-side from the series task’s `RecurrenceRule` (same source `recover_held` uses). If a task payload lacks recurrence, Recover affordance waits on task detail / review response — **no** client-side “probably recurring” heuristic.

## 2. Proposed API dependency — read-only recovery review + binding

**Verdict:** **PROPOSED DEPENDENCY** (not landed). Lands in the same coding-unlock family as T2-REC-UI (or as a tiny prior API commit under that unlock) — **not** granted by this planning packet alone. Prior draft @ **`6a30968`** remains **NOT ACCEPTED**.

### 2.1 Shape (consistent with held disposition POSTs)

| | |
| --- | --- |
| **Method / path** | **`POST /api/v1/schedule/held-misses/{task_id}/recover/review`** |
| **Why POST not GET** | Body carries named episode + revision + optional successor choice / catch-up overrides (same family as leave/release/skip/recover). Avoid GET-with-body. |
| **Mutation** | **None — true read-only** (see §2.5). No nested savepoint writes; no catch-up Task; no disposition / event / membership / revision / schedule-run / provider side effects — including writes that would later roll back. |
| **Reuse** | Call the **same pure projection helpers** (§2.5) used by `recover_held` for successor, catch-up default remaining, C2 predicate, and projected rolled bounds — **do not** fork RRULE policy into the web client |
| **AuthZ** | Same owner + task ownership as recover |
| **Clock** | **Server** issues `authorize_instant` at review compute — **not** browser/app clock as authoritative cadence |

**Not** `POST /schedule/previews`. **Not** calculate/replan. **Not** provider refresh.

### 2.2 Request (`RecoverHeldReviewIn` — illustrative)

| Field | Required | Notes |
| --- | --- | --- |
| `disposition_id` | **yes** | Named episode only |
| `expected_revision` | **yes** | Stale → **409** (parity with recover; no silent continue) |
| `accept_past_ack` | no | Default false |
| `step_count` | no | Optional fixed extra steps |
| `abort` | no | If true, review may short-circuit as aborted intent (still no writes) |
| `catch_up_due_at` / `catch_up_start_no_earlier_at` / `catch_up_start_no_later_at` / `catch_up_deadline_at` | no | Operator-edited catch-up window for gate preview — UTC wire of the **wall actually under review** (§3.5) |
| `catch_up_remaining_minutes` | no | Override incl. **0**; omit → server default |

Same exclusivity rule as `RecoverHeldIn`: at most one of `accept_past_ack` / `step_count` / `abort`.

**Removed vs bounce draft:** client-supplied `authorize_instant` as the review clock. Review **does not** accept a free-typed or browser-clock cadence control. (Authorize still receives the **server-issued** instant **inside** the binding — see §2.4.)

### 2.3 Response (`RecoverHeldReviewOut` — operator review pane)

All fields below are **required for the UI contract** unless marked optional. Timestamps on the wire are timezone-aware UTC instants representing the walls the operator is reviewing (§3.5).

| Field | Purpose (Dex “MUST SEE before authorize”) |
| --- | --- |
| `disposition_id` / `task_id` / `episode_key` | Named episode identity |
| `expected_revision` | Binding input shown / resent at authorize |
| `authorize_instant` | **SERVER-issued** review instant (stable for this response) — displayed human-readable; **not** operator-typed; **not** browser clock as authority |
| `review_binding` | Stateless authenticated token **or** digest (see §2.4) — opaque to UI except round-trip |
| `contract_version` | Short version string / enum for this review↔authorize contract (included in binding) |
| `cadence` | `{ "is_fixed": bool, "timezone": "<IANA>", "rrule_summary"?: string }` — **authoritative** rule zone + fixed vs completion-anchored (§1.4) |
| `eligibility` | `{ "recurring": bool, "one_off_use_release": bool }` — **authoritative**; non-recurring → reject recovery / steer to release |
| `next_normal` | Computed target: `due_at`, projected `start_no_earlier_at` / `start_no_later_at` / `deadline_at` (nulls preserved), `landing_is_past`, `accept_past_required` |
| `next_normal_effort` | `{ "worked_minutes": 0, "remaining_minutes": <estimate> }` — full next-normal restart |
| `catch_up` | Defaults + gated projection: `remaining_minutes_default`, `remaining_minutes` (after override if any), `due_at` / bounds / deadline as supplied or null, `usable_dates_ok` / reject code if catch-up window invalid |
| `historical_work` | Miss-era treatment: `worked_minutes`, `remaining_minutes`, `estimated_duration_minutes`, `ledger_retained_on_series`: true, `progress_entry_count` (or id-set length) — **no** duplicate onto catch-up |
| `c2` | `{ "blocks_prevent_next_normal": bool, "code": "BLOCKS_PREVENT_NEXT_NORMAL" \| null, "detail": "…" }` — limitation honesty; **no** remediation instructions to delete/unpin |
| `successor_choice` | `{ "status": "ok" \| "FIXED_PAST_REQUIRES_CHOICE" \| "RECURRENCE_NO_SUCCESSOR" \| "RECOVERY_REQUIRES_RECURRING" \| …, "accept_past_applied_if_authorized": bool }` |
| `review_ok_for_authorize` | bool — true only when authorize with **this** binding would pass gates known at review (C2 clean, successor resolved or explicit choice present, catch-up dates ok). False → UI disables Authorize and shows code |

**Errors (HTTP):** **404** missing disposition/task; **409** stale revision / `CONFLICT_TERMINAL`; **422** with existing codes where review can diagnose without write (`RECOVERY_REQUIRES_RECURRING`, `RECURRENCE_NO_SUCCESSOR`, `BOUNDS_ROLL_INDETERMINATE_LOCAL`, `BOUNDS_STILL_MISSED`, `FIXED_PAST_REQUIRES_CHOICE` as structured outcome preferred over hard 422 when choice is still available).

### 2.4 Server-verifiable review↔authorize binding (not UI echo)

**Problem (bounce):** Existing `RecoverHeldIn` accepts no reviewed successor digest / intent digest / binding token. Resending operator-chosen fields (or echoing a client `authorize_instant`) cannot detect that authorize disagrees with what the review pane **displayed**.

**Mechanism (narrow, required):**

1. **Coverage of the binding** (canonical bytes → HMAC / signed token **or** equivalent authenticated digest; server secret / key already used for app auth material — exact crypto left to impl, semantics fixed here). Binding material **must** include at least:
   - **owner_id** + **task_id** + **disposition_id** / **episode_key**
   - **expected_revision** (scheduling revision asserted at review)
   - **canonical submitted intent** — normalized successor choice (`accept_past_ack` / `step_count` / `abort` exclusivity) + catch-up field presence/values with **omit vs null** preserved + remaining override omit-vs-value
   - **stable SERVER-issued `authorize_instant`** from the review response (completion-anchored cadence uses **this** instant — not a later browser/server “now” at authorize)
   - **exact projected targets** returned to the UI: successor due + rolled next-normal bounds/deadline + next-normal effort + catch-up remaining/dates as reviewed
   - **`contract_version`** (and any schema discriminator needed to prevent cross-version replay)

2. **Stateless:** Prefer a **self-contained authenticated token/digest** the UI round-trips. Verification = recompute projection under lock from live state + compare to binding claims / digest. **No persisted review row required.** (Impl may add short-lived server cache later; it is **not** required by this contract.)

3. **Authorize (`POST …/recover`) changes (same unlock family):**
   - Accept `review_binding` (token/digest) **in addition to** the explicit intent fields (still sent for clarity / gate UX).
   - Under lock + revision assert: **recompute** the pure projection for the submitted intent using the **bound** `authorize_instant` (from binding — **not** a fresh wall clock, **not** a free-typed ISO field).
   - **Reject** (409/422, fail-closed) when: binding MAC/signature invalid; owner/task/episode mismatch; revision drift; canonical intent bytes ≠ submitted body; recomputed successor / rolled dates / effort ≠ bound projection; temporal gates now fail; C2 now blocks. **No** silent shift to a new next-normal.
   - Stale temporal gates (past landing without choice, catch-up unusable dates, DST indeterminate) → **fail closed** — same codes as today where applicable.
   - **409:** no auto-retry; single in-flight request; show conflict; **refresh review** (new server instant + new binding).
   - Idempotent already-recovered same `disposition_id` → **200** with existing `catch_up_task_id` — UI treats as success (toast + link), not a second create.

4. **Browser clock is not authoritative cadence.** Display may show the server-issued instant in local labels; refresh/re-open deliberately requests a **new** review (new server instant + binding). Idle timers / skew between browser and API **must not** redefine completion-anchored next-occurrence.

5. **UI obligations tied to binding** (expanded in §3.3):
   - After **any** relevant edit (successor choice, catch-up remaining, catch-up dates, abort toggle, disposition/task identity change), mark review **stale**, disable Authorize, and require a **new** matching `recover/review` whose displayed fields + binding match the current form.
   - Discard / ignore **in-flight review responses** that correspond to **older** edit generations (out-of-order / late responses must not re-enable Authorize on stale content).

### 2.5 True read-only — pure projection / DTO seam (expanded)

A single “review returns projected fields without DB mutation” adjunct is **insufficient** (bounce). Review and authorize **must** share a named seam; review must be **observably** non-writing even under failure.

#### 2.5.1 Named seam

| Name (illustrative) | Responsibility |
| --- | --- |
| **`project_recover_held_review`** (pure) | Given owner/task/disposition identity, revision expectation inputs, authorize instant, and canonical intent → return a **DTO** (`RecoverHeldProjection` / review-out body fields): eligibility, cadence, successor choice status, next-normal dates/effort, catch-up defaults/gates, historical-work summary, C2 predicate result, `review_ok_for_authorize`. **No Session writes.** |
| **`issue_recover_review_binding`** | Canonicalize DTO + intent + ids + revision + server `authorize_instant` + `contract_version` → authenticated digest/token. |
| **`recover_held` (mutate)** | Assert revision under lock → call **same** `project_recover_held_review` → verify binding → **then** perform catch-up create / series advance / disposition terminalize / membership / rev bump inside the existing nested-savepoint mutate path. |

Projection helpers already accepted for mutate (`_select_next_due_occurrence_local`, `_verify_due_wall_clock`, catch-up remaining default, C2 assert, bounds-roll **math**) must be reachable **without** going through `_apply_series_bounds_roll` / task create / disposition event writers. If today’s helpers mutate by side effect, coding unlock **splits** pure compute from apply — do not “review via mutate+rollback.”

#### 2.5.2 Forbidden on the review path (even transiently)

| Forbidden | Why |
| --- | --- |
| ORM attribute assignment on `Task` / disposition / progress / membership that would flush | “Rolled back write” still races, dirties identity map, and lies about read-only |
| `Session.flush` / nested savepoint begin that exists to stage writes | Not read-only |
| Creating Tasks, disposition events, epoch membership rows, schedule runs | Observable or rolled-back mutation |
| Bumping `scheduling_revision` | Observable mutation |
| Provider / Graph / Google / calendar refresh calls | Side effects outside DB |
| Relying on `expire_all` / rollback of intentional writes as the read-only strategy | Bounce: true read-only means **no writes**, not write-then-undo |

#### 2.5.3 Snapshot / lock / refresh discipline

| Concern | Contract |
| --- | --- |
| **Review read consistency** | Load task + disposition + blocks needed for C2 with a **coherent snapshot** (single request; no half-updated identity map). Prefer read-only session / `autoflush=False` for the review unit of work. |
| **Authorize** | Existing mutate lock + `assert_scheduling_revision`; recompute projection under that lock before writes. |
| **Between review and authorize** | Binding + revision assert detect drift; UI refreshes review on 409 / stale. |
| **Refresh** | Explicit operator refresh/re-open → new server `authorize_instant` + new binding + new displayed targets. |

#### 2.5.4 API evidence required for read-only (not UI-simulated only)

Named cases in §4 (**A-RO***, **A-BIND***) must use disposable DB + **fresh Session** before/after review (including exception paths) proving: no new Task / disposition event / membership / revision bump / schedule run; cross-owner 404 isolation; terminal disposition / revision drift 409; and **real concurrent** review vs authorize (second session) without review leaving durable writes.

### 3.2 Fields — operator MUST SEE before Authorize

Rendered from **`recover/review`** (authoritative), not inventing client RRULE:

1. **Next-normal target** — due + projected bounds/deadline shown in **rule timezone** with explicit **rule-zone** label (from review `cadence.timezone`)  
2. **Cadence / zone** — fixed vs completion-anchored; IANA rule zone; DST honesty via labeled walls + server gap/fold codes  
3. **Full next-normal effort** — worked **0** / remaining **estimate**  
4. **Catch-up** — remaining default (incl. **0** when live remaining is 0); editable remaining; date/bounds inputs per **Option A** (§3.5)  
5. **Historical-work treatment** — miss-era worked/remaining/estimate retained on series ledger; catch-up starts clean; no duplicate of logged minutes  
6. **C2 limitation** — if `blocks_prevent_next_normal`: clear reject copy that recovery **cannot** proceed while same-task blocks/pins poison next-normal; **do not** offer or imply delete/unpin / “manual clear blocks” as the supported C2 remedy for this slice  

Authorize button enabled only when: review is **fresh** (not stale), `review_ok_for_authorize`, binding present, **and** (if `accept_past_required`) operator completed an explicit choice (accept past / step / abort).

### 3.3 Gates & actions

| Action | Contract |
| --- | --- |
| **Open Recover** | Fetch settings rev + named held row; call **`recover/review`** (server issues `authorize_instant` + `review_binding`); show pane |
| **Refresh review** | Explicit refresh/re-open only → new server instant + binding; never silently redefine cadence from browser clock / idle timer mid-pane |
| **Any relevant edit** | Successor choice, catch-up remaining, catch-up dates (incl. clear/omit), abort — **immediately** mark review **stale**, disable Authorize, bump local edit generation; require new matching review before Authorize re-enables |
| **In-flight / out-of-order** | Discard review responses whose request generation ≠ current; late responses must **not** clear stale or enable Authorize |
| **Fixed past** | Require **Accept past** **or** **Step further (N)** **or** **Abort** — no silent auto-loop |
| **Accept past** | Explicit ack copy: may immediately need-decision again on past landing (visible honesty; not a bug) |
| **Abort** | Close pane; **no** recover POST |
| **Catch-up remaining** | Default from review; override allowed including **0**; never auto-fill historical worked as catch-up worked |
| **Authorize** | Single `POST …/recover` with reviewed intent fields **+** `review_binding` (server-issued instant carried by binding); disable controls while pending; **no** 409 auto-retry |
| **Binding / target mismatch** | Surface API reject; refresh review; **no** silent success |
| **Success** | Toast; show **catch-up task link**; `invalidateAfterHeldMutation` (+ `["task", seriesId]`, `["task", catchUpId]`); held list drops recovered episode; series detail refresh |
| **Idempotent success** | Same disposition already recovered → success UX with existing catch-up link |
| **Leave / skip / release** | Unchanged; Recover does **not** save unrelated task-title/notes/duration edits — only catch-up + successor fields in the recover request. Date-first release path remains separate (do not piggyback dirty unrelated draft fields into recover) |

### 3.4 Authorize instant — server-issued; no technical type-in

- UI displays the **server-issued** `authorize_instant` from the latest fresh review (human local time + zone label for readability).  
- **Forbidden:** a free-text ISO / epoch field for Trish to type as the recovery control.  
- **Forbidden:** treating browser/app “now” as the completion-anchored cadence authority.  
- Operator may **refresh review** deliberately; authorize sends binding that embeds the **displayed** server instant.

### 3.5 Date input zone policy — **Option A** (chosen)

**Choice:** **Option A** — reuse browser-local `datetime-local` with a conspicuous **edit-zone** label and separate **rule-zone** target display.

**Rationale:** Accepted T2-S2-UI already documents and implements `datetime-local` as **browser-local** (`taskDetailDraft.ts` / TaskDetailPanel). Displaying `RecurrenceRule.timezone` on a label does **not** make the widget parse in that zone; claiming Option B (IANA wall parsing in the web client) would conflict with accepted held/date-first UX and invite silent `Date` conversion bugs. Option A stays **truthful**: edits are browser-local; rule-zone is for **reviewed targets** and diagnostics; server remains authority for gap/fold on rule-zone walls.

**Exact policy:**

| Concern | Rule |
| --- | --- |
| **Edit widgets** | Catch-up due/bounds/deadline editors = `datetime-local` in **browser local** zone |
| **Edit-zone label** | Conspicuous label: e.g. “Editing in **\<browser IANA\>** (browser local)” via `browserTimeZoneLabel()` — never imply rule-zone input |
| **Rule-zone display** | Next-normal (and any server-projected catch-up defaults) formatted with `formatInstantInZone(…, cadence.timezone)` + explicit **rule-zone** IANA label from review |
| **No masquerade** | Forbidden: `new Date(...)` / ISO round-trip presented as “typed in rule zone.” Forbidden: feeding browser-local strings through ZoneInfo(rule) on the client as if they were rule walls |
| **Wire values** | UTC instants **must** represent the **wall the operator actually reviewed/edited**. Unchanged fields: **omit** (do not re-send) so minute-precision widgets do not truncate **seconds/milliseconds**. Explicit clear → **null**. Preserve omit-vs-null in binding canonicalization |
| **Gap / fold** | Server fail-closed (`BOUNDS_ROLL_INDETERMINATE_LOCAL` etc.) on rule-zone projection; UI surfaces diagnostic — **no** client snap |
| **Browser zone ≠ rule zone** | Required evidence case (§4 **U-Z1** / **A-Z***) — labels differ; wire instant matches browser-local edit, not a silent rule-zone reinterpretation |
