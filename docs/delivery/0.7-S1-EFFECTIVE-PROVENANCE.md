## Goal

Complete the **S1 read contract** so callers get structured, actionable answers for “what affects this task / this date?” without running the scheduler or implying S2 eligibility.

## Explicitly OUT (S2 / later)

| Out | Why |
| --- | --- |
| Free-slot calculation, busy-event subtraction, “where can this task fit?” | Scheduler work |
| Inherit / No limit / keep-in-one activation; General as placer eligibility | S2 cutover |
| Pin future-tail reservation math presented as placement effort | Only expose if actually calculated (it is not in S1 bridge) |
| Rewriting history or triggering schedule runs from a read | Read-only |
| Full duration conversion / inheritance UX | Next duration slice — S1 may expose **active** original/worked/remaining + explicit block bounds only |

---

## What S1 must tell the caller

| Area | Expectation |
| --- | --- |
| **Actual values and origins** | Which map/settings apply, their IDs and values, and whether they came from task, project, epic, or user settings. Clearing an assignment must visibly restore inheritance. |
| **Active versus saved configuration** | What the **legacy scheduler uses now**, alongside relevant **saved** configuration waiting for S2. A saved policy must not masquerade as active eligibility. |
| **Working-policy divergence** | If saved Working windows differ from legacy working-hours settings, show **both** and explain which is active (Tue–Sat config-only; direct settings edits). |
| **Date-specific effects** | Optional date on the effective read (API + CLI parity). With a date: applicable dated override, timezone, scope, what it replaces. Without a date: general configuration + disclose that dated resolution was **not** performed. |
| **Empty / missing / unsupported** | Distinguish (1) no allowed windows, (2) no assignment → fallback applies, (3) saved but not supported by current scheduler. Do not collapse all three to “nothing configured.” |
| **Live versus historical** | “What affects this task?” = current configuration. “Why this placement?” = recorded run explanations (unchanged path). Neither read triggers scheduling or rewrites history. |
