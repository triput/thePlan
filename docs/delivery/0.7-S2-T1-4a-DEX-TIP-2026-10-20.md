### Real concurrent DB sessions

Two `SessionLocal` connections. Resolve flushes and **does not commit** until `pg_locks` shows a **new ungranted** advisory waiter on namespace `1886415953` whose query is `pg_advisory_xact_lock`. Ingest is blocked in that lock. Final rows alone are not the concurrency proof.

Ordering is **resolve holds the lock first** (deterministic). Ingest-wins is not a separate sample; the waiter is the overlap.

| Case | Test | Coherent outcome asserted |
| --- | --- | --- |
| Sibling race | `test_real_concurrent_sibling_race` | One policy, one decision. A pending cleared only after commit. B stays pending, latch retained, B's transparency write is invisible until the lock releases. |
| First-policy race | `test_real_concurrent_first_policy_race` | No policy row visible to other sessions during the hold. After both commit: exactly one policy, one decision, A cleared, B still pending. |
| New-instance race | `test_real_concurrent_new_instance_race` | C is not visible during the hold. After commit, C has an **automatic** baseline (policy was visible; not a manual decision). |

### Real sessions, not concurrent

| Case | Test |
| --- | --- |
| Rollback / no partial write | `test_real_session_rollback_no_partial_write` — resolve flushed (policy, decision, baseline, pending cleared), then `rollback`. New session: no policy, no decision, no baseline, pending still true. |
| Restart / new session | `test_real_session_restart_persists_resolved_and_latched` — committed resolve: new session `collect_inputs` trust ok. Later occupancy disagreement committed: another new session still sees latch, pending, trust not ok. Decision count stays 1. |
| Apply recollect gate | `test_apply_recollect_gate_fresh_session_without_live_apply` — fresh session calls `collect_inputs` twice and `require_busy_input_trust`, the same gate `apply_schedule_preview` uses before domain writes. No `SchedulePreview`, no live Apply. Resolved passes; latched pending raises `BusyInputTrustError`. |
