## 1. Normative product intent

Operators trigger a **covering refresh**: import and reconcile **local busy cache** for **explicitly selected calendar subscriptions** over an **explicit visible time window**, **without**:

- changing which calendars stay enabled (`PUT …/subscriptions`), or  
- writing remote provider calendars (no export mirror deletes, no subscription metadata writes beyond what §4.1 names), or  
- implying Preview/Apply authorization from a successful subset refresh.

**Covering** (per subscription, on success): provider batch for the effective window fully drained; coverage minted ⊇ operator-visible bounds (after any documented pad widening); Google full-window reconcile (immovable rows missing from batch handled per existing full path); Microsoft `calendarView` / `ms_view` path unchanged.

**Legacy route unchanged:** `POST /api/v1/calendar/accounts/{account_id}/sync` retains current semantics (all enabled subs on one account; incremental when Google cursor valid; includes `retry_pending_deletions` and export-side remote DELETE retries). **No** `force_covering` flag on legacy sync.

## 2. API surface (covering-only)

### 2.1 Endpoint

`POST /api/v1/calendar/covering-refresh`

**Auth / ownership:** Same session auth as existing calendar routes. Caller must own every `subscription_id`. Cross-owner IDs → **422** with explicit `CALENDAR_SUBSCRIPTION_NOT_ELIGIBLE` (or equivalent stable code) per row in preflight — **never** silently dropped from the request set.

**Body (JSON):**

| Field | Required | Semantics |
| --- | --- | --- |
| `subscription_ids` | yes, non-empty, bounded (see §2.3) | Explicit operator selection; **not** inferred from “all enabled” |
| `window_start`, `window_end` | yes | **Operator-visible range** — timezone-aware instants (ISO-8601); interpreted in UTC after normalization; `end > start` |
| `scheduling_horizon_label` | optional | When present, names the horizon used for **readiness** fields (default: server `required_coverage_window(settings, now)` bounds) |

**Forbidden on this route:** `force_covering=false`, `mode=incremental`, or any parameter that selects non-covering ingest. Incremental catch-up remains **only** on legacy account sync.

**Response envelope:** HTTP **200** only when the request passed auth/validation/preflight and orchestration **finished** (success, partial per-sub failure, or zero-success orchestration — see §2.4). **401/403/422** for auth, validation, ineligible targets, range/target limits. **502/503** only for pre-orchestration infrastructure faults where **no** per-sub outcome can be persisted honestly (not as a substitute for mixed per-sub provider failure).

### 2.2 Window policy (no quiet redefinition)

| Concept | Rule |
| --- | --- |
| `window_requested` | Echo `window_start` / `window_end` after validation |
| `window_effective` | Bounds actually used for provider pull + coverage mint for **this action** |
| Pad widening | Allowed **only** when collect/scheduling pad rules require it; must set `window_widened: true`, `window_widen_reason` (enum), and **both** requested and effective bounds |
| **Freeze:** | Pad widening **must not** replace the operator-visible range in UI copy; it supplements pull bounds. **Scheduling-horizon readiness** (§5) uses `required_coverage_window` separately — do **not** silently set “visible range = whole horizon” |

### 2.3 Bounded inputs

| Limit | Contract |
| --- | --- |
| Max span | `window_end - window_start` ≤ **42 days** (initial cap; tunable constant — must reject over-max with `CALENDAR_WINDOW_TOO_LARGE`) |
| Max targets | ≤ **20** `subscription_ids` per request |
| Empty / duplicate IDs | 422 |
| Disabled / missing sub | Preflight error row; **not** pulled |
| Identity-blocked (T1-F) | Preflight error row with stable code; **not** pulled |
| Account disabled / disconnected | Preflight error for subs on that account |

**Ownership preflight** runs **before** any provider HTTP for that account (token fetch may occur for eligibility checks only where already required by `prepare_subscriptions_for_sync` — see §4.1).

### 2.4 Overall outcome vs per-sub results

| Field | Semantics |
| --- | --- |
| `overall_outcome` | `success` \| `partial` \| `failed` \| `no_op` — **mandatory**; derived from per-sub rows + preflight rejections |
| `results[]` | One row per **requested** `subscription_id`: preflight failures included with `phase=preflight`; pull failures with `phase=import` |
| `action_summary` | Counts: `requested`, `preflight_rejected`, `import_ok`, `import_failed` — **not** a readiness claim |

**`no_op`:** All requested subs preflight-rejected, or orchestration aborted before any import with zero durable success (document cause).

**Mixed OK:** 200 + `overall_outcome=partial` is normal; client must not treat HTTP status alone as “all calendars fresh.”

## 3. Boundary 1 — Import-cache only (**NEVER** remote calendar writes)

### 3.1 Forbidden side effects on covering-refresh

The covering-refresh path **must not** invoke:

| Seam | Why excluded |
| --- | --- |
| `retry_pending_deletions(… delete_google_event / delete_microsoft_event)` | **Remote DELETE** of provider events (export mirror tombstones) |
| Export / mirror writers | Any code path that creates/updates/deletes provider events for scheduled blocks |
| `PUT …/subscriptions` | Persistent enable/disable selection |
| Subscription-setting mutations beyond §3.2 | Role changes, mirror flags, etc. |

**Required:** A dedicated **`import_covering_subscription_cache`** (name illustrative) entry seam that performs: token read → **subset-filtered** eligible subs → provider **read/list/calendarView** → local upsert/reconcile → coverage mint → failure sidecar — **without** tombstone retry composition.

**Deliberate-delete preservation:** Rows/events suppressed because the operator **verified** intentional remote deletion (Trish Decision, Track 3 policy) remain suppressed via **`suppressed_external_ids` passed into apply** — sourced from **local tombstone state without issuing new provider DELETEs** on this route. Implementation must **read** pending-deletion / suppression sets for import skip logic; it must **not** call `delete_event` on the provider.

### 3.2 Allowed preflight / `prepare_subscriptions_for_sync` effects (named)

`prepare_subscriptions_for_sync` (and primary bootstrap) may:

- Canonicalize calendar alias / external id mapping (T1-F class)  
- **Read** provider calendar list for identity reconciliation  
- Bootstrap **primary** subscription row when policy says account lacks one  

**Contract requirements:**

| Effect | Reporting |
| --- | --- |
| Canonicalization changed a sub’s pull identity | `results[].preflight_effects[]` includes `canonicalize_identity` |
| Primary bootstrap created/updated a sub | `preflight_effects[]` includes `bootstrap_primary` — counts as **out-of-request** mutation; must **not** add undeclared subs to import set |
| Sub ineligible after prepare | Explicit preflight rejection — **never** broaden requested subset to “all enabled on account” |

**Tests (mandatory):** Provider HTTP mock records **zero** DELETE/PATCH/POST to event write endpoints; **zero** calls to `delete_google_event` / `delete_microsoft_event` from covering-refresh orchestration (monkeypatch/spy on tombstone retry entrypoint).

## 4. Boundary 2 — Transaction ownership (nested savepoint ≠ per-sub durable commit)

### 4.1 Observed legacy behavior (why contract differs)

Today: `sync_account_events` uses nested savepoints per subscription, but **`sync_calendar_account` commits once** after return. Google/MS loops **raise** on first subscription failure → earlier nested commits may already be **merged into the session** and become durable on outer route commit. Failure sidecars (`_commit_refresh_failure`) may persist even when sibling subs succeeded. **Nested savepoint commit ≠ independent per-sub transaction boundary.**

### 4.2 Required covering-refresh transaction model

| Rule | Requirement |
| --- | --- |
| **Per-sub durable unit** | Each subscription import success/failure must be **independently committed or rolled back** such that a **fresh SQLAlchemy session** read-back sees: success rows **iff** `results[].status=ok`; failed sub **iff** sidecar/failure state with **no** false `coverage_success_at` |
| **Cross-sub failure** | Sub A success **must survive** sub B failure on same account (and cross-account) |
| **Busy/trust revision** | Compare before/after **per owner** using existing Boundary B helpers; **finalize** revision bump decision when **all targeted subs for that owner** in this request have reached terminal import state **or** when partial completion changes trust — even if a **later** account in the same POST fails |
| **Stale invalidation** | When revision bumps, response includes `scheduling_revision_bumped: true` and **must not** claim `readiness.scheduling_ready=true` unless §5 rules satisfied |

**Orchestration commit pattern (normative):** For each subscription target: begin transaction → import covering → commit **or** rollback → append `results[]` → **only then** proceed to next target. Owner-level revision evaluation runs at account boundary (after all subs requested on that account for this POST) and at final POST boundary for multi-account.

**Forbidden evidence claims:** Rolling back a failed sub must **not** leave `results[].status=ok`; success must **not** appear for subs whose coverage mint was rolled back.

## 5. Boundary 3 — Action results ≠ scheduling readiness

### 5.1 Two mandatory report layers

| Layer | Scope | Purpose |
| --- | --- | --- |
| **`coverage_action`** | **Requested** `subscription_ids` only, over `window_effective` | Honest feedback for the operator gesture |
| **`scheduling_readiness`** | **All enabled** subscriptions on owner, over **named scheduling horizon** | Answers “can collect/Apply treat busy as trustworthy for scheduling?” — **not** authorization to Apply |

**Freshness evaluator:** `evaluate_calendar_freshness(db, owner_id, settings, now, required_start=…, required_end=…)` always considers **all enabled** account/sub pairs — **never** a supplied subset only.

**Busy-input trust:** `evaluate_busy_input_trust` for the same scheduling horizon window is **mandatory** in `scheduling_readiness` when the response claims any readiness field. **`busy_input_trust` is not optional** if copy implies scheduling-trustworthy busy.

### 5.2 Readiness shape (timestamped assessment)

```json
"scheduling_readiness": {
  "evaluated_at": "<ISO-8601 UTC>",
  "scheduling_revision": "<int>",
  "horizon": { "start": "...", "end": "..." },
  "freshness_all_enabled": { /* CalendarFreshnessTrust.to_dict() */ },
  "busy_input_trust": { /* same contract as GET …/busy-input-trust */ },
  "scheduling_ready": false,
  "blocking_summary": ["…"]
}
```

| Field | Rule |
| --- | --- |
| `scheduling_ready` | `true` only if `freshness_all_enabled.ok` **and** busy-input trust acceptable for horizon **and** no uncovered **enabled** sub outside requested set still blocks horizon (honest `blocking_summary`) |
| `evaluated_at` | Wall-clock UTC at evaluation instant — **not** Apply authorization |
| Subset success | `coverage_action.all_requested_covering_ok` may be `true` while `scheduling_ready` is **false** (other enabled calendars stale) |

**Uncovered inputs:** Enabled subs **not** in `subscription_ids` remain subject to freshness/trust; response must list them in `blocking_summary` when they block horizon readiness.

## 7. Boundary 5 — Cross-account orchestration (replaces “F6 weak” reuse)

**Prerequisite statement:** Observed F6 proof @ **`8c83c03`** documents **single-account** `sync_account_events` lock/fetch order. **Cross-account subset orchestration with independent per-sub commits is new** — existing F6 test **does not** cover it without extension.

### 7.1 Required orchestration design (implementation phase)

| Concern | Contract |
| --- | --- |
| **Lock order trace** | Documented per-request trace: preflight → per-account token → per-sub `subscription_refresh_lock` → `lock_owner_scheduling` at defined boundaries — **no broad lock rewrite** in Phase 1, but **must** match written trace in tests |
| **Disconnect/disable races** | Before provider pull per sub: re-fetch subscription + account enabled flags; if disabled mid-flight → terminal `import_aborted` row, no false success |
| **Contention** | Second concurrent covering-refresh on same sub → **409** or structured retry (`REFRESH_ALREADY_RUNNING`) — bounded wait **not** required in Phase 1 |
| **Multi-owner** | Single POST **single owner** (all subs must share `owner_id`); else 422 |

**Prerequisite if reuse unsafe:** If independent commits cannot be implemented without reordering Microsoft pre-lock fetch vs `lock_owner_scheduling`, implementation **stops** for Dex decision — **no** silent inheritance of “F6 weak qual.”

**Clock-slide:** Remains **separately open** (Track 1). Response uses real `now` for freshness; **does not** claim automatic preview invalidation on wall-clock slide.
