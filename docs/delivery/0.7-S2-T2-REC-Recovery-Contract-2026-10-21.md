### 2.1 Scope

- **Recurring-only** reviewed recovery.
- Authors a **distinct catch-up one-off** beside **next-normal** on the live series task.
- Series advancement **must not** falsely complete missed work (must **not** call `complete_task` on the miss).
- Completing the catch-up one-off **must not** advance the series.

### 2.2 Progress / logged work (quantitative pin: 60 / 25 → remaining 35)

| Identity | Live `worked_minutes` | Live `remaining_minutes` | History |
| --- | --- | --- | --- |
| Miss episode (historical) | n/a | n/a | Disposition + immutable `bounds_snapshot` + `episode_key`; **snapshot** miss-era worked total (= **25**) + **explicit set of `task_progress_entries.id` present at authorize** (that id-set **is** the miss-era epoch); append-only `task_progress_entries` **remain** on series `task_id` |
| Catch-up one-off (new Task) | **0** at create | **Default = last confirmed remaining** — prefer live `remaining_minutes` at snapshot (**35** in example); if live remaining is **null** → default = `estimated_duration_minutes` (placement fallback); if live remaining is **0** → catch-up default remaining = **0** (operator may override at review to positive). **Never** invent from original−worked. Adjustable by Trish during review — not automatic full restart to **60** | Fresh ledger only after create; **does not** receive the historical 25 |
| Series next-normal (same Task, advanced) | **0** after reset | **`estimated_duration_minutes`** (full estimate, **60** in example) | Same historical ledger rows retained; miss-era 25 **must not** remain as live worked; entries created **after** reset (new ids) are next-normal epoch |

**Never:** duplicate logged minutes onto both live identities; leave series live at 25/35 after advance; delete/move series ledger rows onto the catch-up; rely on timestamp vs authorize clock alone for epoch boundary.

### 2.3 Cadence

- **Completion-anchored** (`is_fixed=false`): recovery **authorization time** (operator authorize / `now` in rule zone) is the **anchor** for the next occurrence — first RRULE instant strictly after authorize, matching today’s completion-anchored skip-of-intermediate-slots.
- **Fixed** (`is_fixed=true`): retain cadence — first RRULE instant strictly after the **missed occurrence’s due** (same step-from-previous_due as today’s fixed `next_due_at`). If the proposed next-normal instant is **still in the past** relative to operator now → **explicit operator review** (accept past landing, step further, or abort) — **no** silent auto-loop to “next future” inside recovery.

### 2.4 What recovery is not

- Ordinary **one-off** same-task retries continue to use **`release_held`** (date-first / atomic bounds). Recovery adds nothing.
- **Post-skip reactivation** stays a **separate later** semantic question — not this contract’s feature, not folded into recovery authorize.

### 2.5 Operator / stacking invariants

- **No automatic backlog.**
- **No silent stack** into tomorrow / next-normal / parallel undeclared holds.

## 3. Engineering contract clauses

Recovery is a **dedicated path** (name illustrative: `recover_held` / authorize-recovery). It is **not** `complete_task`, **not** `release_held`, **not** a calculate side effect.

### C1 — Progress-ledger / correction attribution after live reset

**Today’s mutation honesty:** `append_progress_entry` always mutates live columns. It **cannot** satisfy historical correction after reset. Recovery coding unlock **must** ship a **ledger-only historical-correction path** (sets `corrects_entry_id`, **no** live mutation) before A2 can go green — **IN recovery coding-unlock family** (not “authorize txn only”), **not** EXCEEDS_SLICE. Ordinary `POST .../progress-entries` after reset is **next-normal logging** and correctly mutates next-normal live columns.

1. **Deterministic epoch/entry boundary (freeze):** At recovery authorize, snapshot onto the disposition: miss-era `worked_minutes`, `remaining_minutes`, `estimated_duration_minutes`, and the **explicit set of `task_progress_entries.id` present at snapshot time**. That id-set **is** the miss-era epoch. Entries created **after** reset (new ids) are next-normal epoch. Do **not** rely on timestamp vs authorize clock alone.
2. Leave all existing `task_progress_entries` rows on the **series `task_id`**. Do **not** rewrite, delete, or re-key them to the catch-up.
3. **Last confirmed remaining for catch-up default:** Prefer live `remaining_minutes` at snapshot. If live remaining is **null** → default catch-up remaining = `estimated_duration_minutes` (same as placement fallback). If live remaining is **0** → catch-up default remaining = **0** (operator may override at review to positive). Never invent from original−worked.
4. **Historical correction after reset — required semantic (protect next-normal):** A correction targeting a miss-era entry (id in snapshot set) **MUST**:
   - Remain on series `task_id` (same-task FK)
   - Append correcting ledger row with `corrects_entry_id` set; update historical attribution/snapshot as needed for audit
   - **MUST NOT** change series live `worked_minutes` / `remaining_minutes` / P0 / inflight signals after reset
   - **MUST NOT** change catch-up Task effort columns or catch-up ledger
   - **MUST NOT** change catch-up remaining or create extra catch-up Tasks
5. New progress on catch-up posts only to the catch-up `task_id`. New progress on next-normal posts only to the series `task_id` after reset (ordinary live-mutating path).

### C2 — Preserved old blocks (**EXCEEDS_SLICE** for safe isolation)

**Readers that do NOT distinguish historical vs current for the same `task_id`** (no episode on `ScheduledBlock` today):

| Reader / path | Effect on miss-era blocks |
| --- | --- |
| `busy_map.load_immovable_busy_sources` / `busy_from_sources` | Treats blocks as busy for the series task |
| `collect.collect_inputs` → `pinned_blocks_by_task` | Pins keyed by task_id without episode split |
| `pin_reservation.reservation_minutes` / `reserved_minutes_from_blocks` | Reserves minutes from pins on that task_id |
| `candidates.load_candidates` / `evaluate_auto_placement` | Placement inputs include same-task blocks |
| `calculate._seed_prerequisite_block_ends`; `calculate` loads all blocks for task ids | All blocks for task ids enter calculate |
| `occurrence_bounds.in_flight_hold_trigger` | Any pin incl. past; reserved>0; any block start≤now; worked>0 → suppress new placement |
| `occurrence_bounds.pin_bounds_conflict` / `evaluate_occurrence_bounds` | Pin/bounds conflict without historical filter |
| `horizon.wipe_unpinned_blocks_in_horizon` (Apply) | Horizon wipe sees same-task blocks |
| `apply.apply_calculation`; `preview_proposal.capture_before_blocks` | Apply/preview treat blocks as live for task_id |

1. Name the readers above as the fail-closed surface: they treat miss-era blocks as **live inputs** for the series `task_id`.
2. **Default:** do **not** silently re-key, delete, or unpin miss-era blocks inside recovery authorize.
3. **Fail-closed at recovery authorize** if any existing `ScheduledBlock` on the series `task_id` would cause next-normal to be treated as in-flight / consume placement effort / block new placement under current readers — specifically if `in_flight_hold_trigger` would be true **or** pin reservation would reduce next-normal placeable minutes. Explicit reject code (illustrative: `BLOCKS_PREVENT_NEXT_NORMAL`). Operator must clear/dispose conflicting blocks via **existing surfaces** **before** authorize — **out of** `recover_held` mutation scope.
4. **EXCEEDS_SLICE (declare prominently):** Safely isolating old blocks so they remain historical evidence **while** next-normal can place (occurrence key on blocks / reader filters across the table above) **exceeds** this recovery-authorize slice. Do **not** pretend authorize can make calculate ignore same-`task_id` pins / past-start blocks without that work.

### C3 — Recurrence end / no successor

1. If `next_due_at` (or equivalent helper with the correct anchor) returns **`None`** (series exhausted / past `ends_on` / no in-frame successor): **fail closed** — no invented occurrence, no silent one-off-only “series” advance, no half-created catch-up without an explicit operator path.
2. Operator path when no successor: reject recovery authorize with an explicit code (illustrative: `RECURRENCE_NO_SUCCESSOR`); disposition stays unresolved_held unless operator chooses leave/skip/release separately.

### C4 — Source-zone bounds / deadline roll including DST + concurrency binding

1. On successful series advance, roll `start_no_earlier_at` / `start_no_later_at` / `deadline_at` (and soft target if present) by the **same calendar delta** as `due_at` advanced, computed in **`RecurrenceRule.timezone`**, then store UTC.
2. Preserve local clock-of-day and wall-date offset relative to the new due. Null fields stay null.
3. **DST / nonexistent / ambiguous local time for recovery bounds roll:** Use **deterministic fail-closed + explicit diagnostics**, reusing the documented calendar-ingest fail-closed posture (`attach_naive_wall_clock` / `IndeterminateLocalTime` semantics) applied to rolled wall times in `RecurrenceRule.timezone`. Do **not** silently snap like `availability_materializer.resolve_recurring_wall` unless product later stamps snap. Reject with explicit code (illustrative: `BOUNDS_ROLL_INDETERMINATE_LOCAL`) + diagnostic naming which bound and gap vs fold. No inverted bounds after a successful roll. (`recurrence.py` / `next_due_at` have **no** gap/fold policy today — do not invent a third policy.)
4. This roll is **recovery-path only** — do **not** silently change today’s `complete_task` / `next_due_at` in this unlock family.
5. **Concurrency / revision binding:** Under `lock_owner_scheduling` + `assert_scheduling_revision`:
   - Bind operator-reviewed successor choice (accept past / step count N / abort), catch-up dates, and series target bounds to the **current** `expected_revision` at authorize.
   - Revalidate successor computation + gates under the lock after refresh (`populate_existing`); if rule/bounds/revision drifted → conflict/reject, **no** partial writes.
   - Separate-session competing recover vs recover; recover vs release/skip; recover vs late-injected rollback/stale rev → **409** / nested savepoint rollback / idempotent replay as applicable (see A5/A6 concurrency cases).

### C5 — Multi-week behavior and exact operator choices

| Rule kind | Next-normal target | If landing still past “now” | Catch-ups for skipped intermediate slots |
| --- | --- | --- | --- |
| **Fixed** | First instant strictly after **missed due** | **Explicit operator review** required before commit (accept past next-normal dates **or** step further / abort). No silent auto-loop | **None** — one catch-up for the held miss only; no multi-miss fan-out |
| **Completion-anchored** | First instant strictly after **recovery authorization time** in rule zone | By construction future (or equal-policy: strictly after); if still unusable under **series gate** → reject | **None** — intermediates skipped (authorize-as-anchor) |

Operator review choices when fixed next-normal is past (must be named in API/UI later; contract-level):

1. **Accept past landing** — commit recovery with that next-normal `due_at` + rolled bounds **with explicit acknowledgement**. Series gate: structural/geometry only — **do not** apply future-time still-past release checks to the series (see §C-gate). Accept-past **does not** promise placeable next-normal at authorize; subsequent calculate/preview may re-hold the past landing (intentional visibility — see §C-gate “visible honesty”).
2. **Step further** — advance one additional fixed step (or N reviewed steps) until accepted / future; still **one** catch-up for the original held episode. Past landing not committed without accept.
3. **Abort** — no writes (txn rollback).

### C6 — Atomic recovery + series changes

Under `lock_owner_scheduling` + `assert_scheduling_revision(expected_revision)`, in **one** nested savepoint / txn:

1. Load **named** `disposition_id` + owner + task; require `unresolved_held` and a **recurring** task (else reject — one-offs use release).
2. Snapshot miss-era progress onto disposition (§C1) — including explicit progress-entry id-set.
3. Fail-closed on conflicting series blocks (§C2) before mutating identities.
4. Create catch-up one-off Task (link to miss episode / `episode_key`); init effort per §2.2 (remaining default = last confirmed remaining; operator-reviewed override allowed in-request).
5. Apply catch-up usable dates; run **catch-up gate** (§C-gate Catch-up).
6. Advance series `due_at` via non-`complete_task` helper + bounds/deadline roll (§C4); run **series gate** (§C-gate Series); reset live series effort (§2.2).
7. Terminalize disposition (illustrative resolution `recovered`); append recovery event; **one** `increment_scheduling_revision`.
8. On any gate/validation failure: **rollback all** of the above — no half-written catch-up, no half-reset series, no resolution change, no rev bump.

### C7 — Named-episode idempotency

| Request | Current state | Result |
| --- | --- | --- |
| recover | already recovered **same** `disposition_id` | **200 idempotent** — return existing catch-up link; **no** second Task; **no** second rev bump; **no** second event required |
| recover | `released` or `skipped` | **409** `CONFLICT_TERMINAL` |
| recover | wrong/missing `disposition_id` | **404** |
| recover | second authorize for same episode after success | Idempotent same identity — **never** invent a second catch-up without explicit re-auth product (out of min scope: no re-auth) |

Identity: **`disposition_id` + owner_id + task_id`** only — never “latest held for task.”

### C8 — Stale / conflicting state

1. Stale `expected_revision` → **409** revision conflict — **precedes** terminal no-op (parity with release).
2. Cross-terminal conflict → **409** `CONFLICT_TERMINAL`.
3. Non-recurring task → reject (use release).
4. Skipped task / skipped disposition → reject recovery (post-skip reactivation is **out of scope**).
5. Concurrent drift under owner lock: refresh named row; do not clear a newer episode via an old id. Revalidate successor + gates after refresh (§C4.5).

### C9 — Scheduling revision / fingerprint effects

1. Successful recovery → **exactly one** `scheduling_revision` bump for the authorize (not per sub-write).
2. Fingerprint-relevant mutations in that same commit: disposition resolution change; series `due_at` + bounds/deadline; series worked/remaining; new catch-up task fields hashed by fingerprint v4. Apply must see **one** coherent stale signal — not multiple conflicting mid-flight revisions.
3. Idempotent replay → **no** further bump / fingerprint churn.
4. Recovery **must not** write dispositions inside `calculate()`.

### C-gate — Usable-dates: Catch-up gate vs Series gate

#### Catch-up gate (always)

Catch-up **MUST always** run the full release usable-dates gate (`_assert_usable_dates_for_release` parity): `unsupported_shape` · `geometry_infeasible` · `latest < now` · `start_floor > latest` (i.e. `max(now, earliest) > effective_latest_start`). Reject **`BOUNDS_STILL_MISSED`** + nested savepoint rolls everything back. Effort via `placement_effort_minutes` on the **catch-up**. Catch-up **never** gets an accept-past exception. **Not** a free-slot / horizon promise.

#### Series gate (after roll)

1. **Always:** structural/geometry validation (`unsupported_shape`, `geometry_infeasible`) on rolled bounds+effort — reject inverted/infeasible.
2. **If next-normal landing is still past operator now AND operator chose Accept past (C5 choice 1):** do **NOT** apply the two future-time / still-past release checks (`latest < now`, `start_floor > latest`) to the series. Commit requires the **explicit acknowledgement** already named in C5 choice 1.
3. **If operator did not accept past** (step further until future, or abort): past landing is **not** committed; if still past without accept → blocked (A7).

#### Visible honesty — what next calculate does with accepted-past series occurrence (Tesla code truth)

- Recovery does **not** write dispositions inside calculate.
- After hold terminalized, calculate no longer skips via `unresolved_held` for that task.
- With past rolled bounds: `evaluate_occurrence_bounds` → typically `occurrence_bounds_miss` (`latest < now`) → skip placement; next preview `stage_auto_misses` may record a **new** `unresolved_held` under the **new** `episode_key` (bounds+deadline digest) — this is a **new hold for the past next-normal window**, **NOT** a second catch-up Task, **NOT** silent stack into recovery, **NOT** hiding the hold.
- If miss-era blocks/pins/worked remain: `in_flight_hold_trigger` may fire instead (see §C2) — suppress new placement.
- **Contract statement:** accept-past does **not** promise placeable next-normal at authorize time; operator may immediately see need-decision again for the past landing — that is **intentional visibility**, not a bug to paper over inside recovery.
