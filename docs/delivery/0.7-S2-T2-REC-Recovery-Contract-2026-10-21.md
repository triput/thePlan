## 2. Locked product semantics (encode exactly)

These are **pinned** by Trish via Dex **`1792625085.114399`**. Engineering must implement them verbatim; overrides require a new Trish/Dex stamp. Bounces **`1792628244.631929`** / **`1792629064.168789`** revise **engineering** clauses only — do **not** reopen product choices.

### 2.1 Scope

- **Recurring-only** reviewed recovery.
- Authors a **distinct catch-up one-off** beside **next-normal** on the live series task.
- Series advancement **must not** falsely complete missed work (must **not** call `complete_task` on the miss).
- Completing the catch-up one-off **must not** advance the series.

### 2.2 Progress / logged work (quantitative pin: 60 / 25 → remaining 35)

| Identity | Live `worked_minutes` | Live `remaining_minutes` | History |
| --- | --- | --- | --- |
| Miss episode (historical) | n/a | n/a | Disposition + immutable `bounds_snapshot` + `episode_key`; **snapshot** miss-era worked total (= **25**) + **explicit set of `task_progress_entries.id` present at authorize** (that id-set **is** the miss-era epoch for that authorize); append-only `task_progress_entries` **remain** on series `task_id` |
| Catch-up one-off (new Task) | **0** at create | **Default = last confirmed remaining** — prefer live `remaining_minutes` at snapshot (**35** in example); if live remaining is **null** → default = `estimated_duration_minutes` (placement fallback); if live remaining is **0** → catch-up default remaining = **0** (operator may override at review to positive). **Never** invent from original−worked. Adjustable by Trish during review — not automatic full restart to **60** | Fresh ledger only after create; **does not** receive the historical 25 |
| Series next-normal (same Task, advanced) | **0** after reset | **`estimated_duration_minutes`** (full estimate, **60** in example) | Same historical ledger rows retained; miss-era 25 **must not** remain as live worked; entries created **after** reset (new ids) are next-normal epoch until a later recovery closes them into a new miss-era |

**Never:** duplicate logged minutes onto both live identities; leave series live at 25/35 after advance; delete/move series ledger rows onto the catch-up; rely on timestamp vs authorize clock alone for epoch boundary.

### 2.3 Cadence

- **Completion-anchored** (`is_fixed=false`): recovery **authorization time** is the **anchor** for the next occurrence — first RRULE instant strictly after the **bound authorize instant** (§C4 / §C5), matching today’s completion-anchored skip-of-intermediate-slots. The operator-reviewed target is bound to that instant; commit **must not** silently recompute from a later wall clock and shift the reviewed target.
- **Fixed** (`is_fixed=true`): retain cadence — first RRULE instant strictly after the **missed occurrence’s due** (same step-from-previous_due as today’s fixed `next_due_at`). If the proposed next-normal instant is **still in the past** relative to operator now → **explicit operator review** (accept past landing, step further, or abort) — **no** silent auto-loop to “next future” inside recovery.

### 2.4 What recovery is not

- Ordinary **one-off** same-task retries continue to use **`release_held`** (date-first / atomic bounds). Recovery adds nothing.
- **Post-skip reactivation** stays a **separate later** semantic question — not this contract’s feature, not folded into recovery authorize.

### 2.5 Operator / stacking invariants

- **Usable-dates gate** — **split** catch-up vs series (see §C-gate); catch-up always full release parity.
- **No automatic backlog.**
- **No silent stack** into tomorrow / next-normal / parallel undeclared holds.
- **Accept-past does not promise placeable next-normal** at authorize time (see §C5 / §C-gate) — intentional visibility if calculate/preview re-holds the past landing.
- **D3 is NOT closed** by this product lock, by ACCEPT of this contract, or by the separate coding unlock.
- **Coding unlock** is a **separate** stamp (same Slack **`1792629456.139259`**, standing scheduler-repair delegation) — bounded to this accepted contract; not broad Track 2 / D3 closure.

## 3. Engineering contract clauses

Recovery is a **dedicated path** (name illustrative: `recover_held` / authorize-recovery). It is **not** `complete_task`, **not** `release_held`, **not** a calculate side effect.

### C1 — Progress-ledger / correction attribution after live reset

**Today’s mutation honesty:** `append_progress_entry` always mutates live columns. It **cannot** satisfy historical correction after reset. Recovery coding unlock **must** ship a **ledger-only historical-correction path** (sets `corrects_entry_id`, **no** live mutation) before A2 / A2b / A2c can go green — **IN recovery coding-unlock family** (not “authorize txn only”), **not** EXCEEDS_SLICE. Ordinary `POST .../progress-entries` after reset is **next-normal logging** and correctly mutates next-normal live columns.

#### C1.1 Deterministic epoch membership (freeze — multi-recovery)

1. At each recovery authorize, snapshot onto **that** disposition: miss-era `worked_minutes`, `remaining_minutes`, `estimated_duration_minutes`, and the **explicit set of `task_progress_entries.id` present at snapshot time**.
2. That id-set is the **miss-era epoch for that authorize**. After a **second** recovery on the same series, the second snapshot includes **all** entries present then — including prior miss-era rows **and** any ledger-only historical corrections already appended — unless assignment has already placed those ids into a **prior closed epoch**.
3. **Disjoint epoch membership (persisted):** Persist a boundary/assignment so each progress-entry id belongs to **exactly one** closed miss-era epoch (or to the open live/next-normal epoch). Do **not** leave membership implied only by “ids present at latest authorize.” Impl may store: per-disposition immutable `miss_era_entry_ids` **plus** an assignment table / epoch_id FK on entries created into an epoch, or equivalent — but membership must be **queryable and disjoint**.
4. Entries created **after** a reset and **before** the next recovery are that interval’s live/next-normal epoch until the next authorize closes them into a new miss-era set.
5. Do **not** rely on timestamp vs authorize clock alone.

#### C1.2 Ledger retention

1. Leave all existing `task_progress_entries` rows on the **series `task_id`**. Do **not** rewrite, delete, or re-key them to the catch-up.
2. **Last confirmed remaining for catch-up default:** Prefer live `remaining_minutes` at snapshot. If live remaining is **null** → default catch-up remaining = `estimated_duration_minutes` (same as placement fallback). If live remaining is **0** → catch-up default remaining = **0** (operator may override at review to positive). Never invent from original−worked.

#### C1.3 Historical correction — smallest required service/API (not broad UX; not safe-reject of the product need)

**Choice for this contract:** **smallest required ledger-only API** with exact delta semantics below — **not** a proposal to safe-reject historical corrections (product already requires miss-era history remain correctable without contaminating live). Do **not** invent broad correction UX (no multi-entry bulk editor, no catch-up rewrite UI, no “fix snapshot” operator surface).

| Surface | Scope |
| --- | --- |
| **Service** (illustrative name) | `append_historical_progress_correction` — **IN** recovery coding-unlock family |
| **API** (illustrative) | Dedicated route **or** progress POST variant that is explicitly ledger-only (not ordinary `POST .../progress-entries`). Reject if invoked as ordinary live-mutating progress |
| **Inputs** | `task_id`, `corrects_entry_id` (must exist on same task), correction payload (`minutes_worked` delta and/or corrected remaining-at-entry semantics as coded), `expected_revision` as required by scheduling parity |
| **Eligibility** | Target entry’s **owning closed miss-era epoch** must be identifiable via persisted membership (§C1.1). Reject if target is in open live/next-normal epoch (use ordinary progress) |
| **Writes** | Append **one** new ledger row on series `task_id` with `corrects_entry_id` set; **append** a **correction-audit** record onto the **owning epoch/disposition** (who/when/target/new-row-id). **MUST NOT** mutate the original immutable authorize snapshot id-set or worked/remaining totals stored at authorize |
| **Correction-chain ownership** | Correcting row inherits **epoch ownership** of the corrected entry (same closed miss-era). Chains stay inside that epoch; they do **not** join a later recovery’s epoch by virtue of “present at later snapshot” alone |
| **Live / catch-up deltas** | **MUST NOT** change series live `worked_minutes` / `remaining_minutes` / P0 / inflight after any reset; **MUST NOT** change **any** catch-up Task effort columns or catch-up ledgers (including prior catch-ups from earlier recoveries); **MUST NOT** create extra catch-up Tasks |
| **Unsupported** | Corrections that would require rewriting immutable snapshots, moving rows across `task_id`s, or mutating live/catch-up → **reject** with explicit code (illustrative: `HISTORICAL_CORRECTION_UNSUPPORTED`) — fail closed for those shapes; do **not** pretend ordinary progress supports them |

#### C1.4 New progress after reset

1. New progress on catch-up posts only to the catch-up `task_id`.
2. New progress on next-normal posts only to the series `task_id` after reset (ordinary live-mutating path).

### C2 — Preserved old blocks (**EXCEEDS_SLICE** for isolation; fail-closed = bounded limitation)

**Honesty:** C2 fail-closed at authorize is an **acceptable bounded engineering limitation**, **not** a preservation solution. It does **not** preserve historical blocks as placeable-safe evidence while next-normal places. Safe isolation (occurrence key / reader filters) remains **EXCEEDS_SLICE** and **explicitly deferred**. Do **not** instruct operators or impl to **delete/unpin history as a workaround** to green authorize.

**Readers that do NOT distinguish historical vs current for the same `task_id`** (no episode on `ScheduledBlock` today):

| Reader / path | Effect on miss-era blocks |
| --- | --- |
| `busy_map.load_immovable_busy_sources` / `busy_from_sources` | Treats blocks as busy for the series task |
| `collect.collect_inputs` → `pinned_blocks_by_task` | Pins keyed by task_id without episode split |
| `pin_reservation.reservation_minutes` / `reserved_minutes_from_blocks` | Reserves minutes from pins on that task_id |
| `candidates.load_candidates` / `evaluate_auto_placement` | Placement inputs include same-task blocks |
| `calculate._seed_prerequisite_block_ends`; `calculate` loads all blocks for task ids | All blocks for task ids enter calculate |
| `occurrence_bounds.in_flight_hold_trigger` | Any pin incl. past; reserved>0; any block start≤now; worked>0 → suppress new placement |
| `occurrence_bounds.pin_bounds_conflict` / `evaluate_occurrence_bounds` | Pin/bounds conflict without historical filter |
| `horizon.wipe_unpinned_blocks_in_horizon` (Apply) | Horizon wipe sees same-task blocks |
| `apply.apply_calculation`; `preview_proposal.capture_before_blocks` | Apply/preview treat blocks as live for task_id |

1. Name the readers above as the fail-closed surface: they treat same-`task_id` blocks as **live inputs**.
2. **Default:** do **not** silently re-key, delete, or unpin miss-era (or any) blocks inside recovery authorize. Clearing conflicting blocks — if needed — is **out of** `recover_held` mutation scope and uses **existing** operator surfaces; that is **not** a contract instruction to delete/unpin history to make recovery work.
3. **Executable conservative predicate (freeze):** At authorize, evaluate **all** existing `ScheduledBlock` rows on the series `task_id` — **both** blocks attributable to the miss-era **and** any other same-task blocks already present. Fail closed if the conservative check says next-normal would be treated as in-flight / have placeable minutes reduced / be blocked under current readers — specifically if `in_flight_hold_trigger` would be true **or** pin reservation would reduce next-normal placeable minutes. Prefer false-positive reject over silent poison. Explicit reject code (illustrative: `BLOCKS_PREVENT_NEXT_NORMAL`).
4. **EXCEEDS_SLICE (declare prominently):** Safely isolating old blocks so they remain historical evidence **while** next-normal can place (occurrence key on blocks / reader filters across the table above) **exceeds** this recovery-authorize slice and stays **deferred**. Do **not** pretend authorize can make calculate ignore same-`task_id` pins / past-start blocks without that work.

### C3 — Recurrence end / no successor

1. If `next_due_at` (or equivalent helper with the correct anchor) returns **`None`** (series exhausted / past `ends_on` / no in-frame successor): **fail closed** — no invented occurrence, no silent one-off-only “series” advance, no half-created catch-up without an explicit operator path.
2. Operator path when no successor: reject recovery authorize with an explicit code (illustrative: `RECURRENCE_NO_SUCCESSOR`); disposition stays unresolved_held unless operator chooses leave/skip/release separately.

### C4 — Source-zone bounds / deadline roll including DST + concurrency binding + authorize instant

1. On successful series advance, roll `start_no_earlier_at` / `start_no_later_at` / `deadline_at` (and soft target if present) by the **same calendar delta** as `due_at` advanced, computed in **`RecurrenceRule.timezone`**, then store UTC.
2. Preserve local clock-of-day and wall-date offset relative to the new due. Null fields stay null.
3. **DST / nonexistent / ambiguous local time for recovery roll:** Use **deterministic fail-closed + explicit diagnostics**, reusing the documented calendar-ingest fail-closed posture (`attach_naive_wall_clock` / `IndeterminateLocalTime` semantics) applied in `RecurrenceRule.timezone` to:
   - the **successor `due_at` wall time itself**, **and**
   - **each** non-null rolled bound / deadline / soft target.
   Fail-closed on successor due **even when all bounds/deadline are null**. Do **not** silently snap like `availability_materializer.resolve_recurring_wall` unless product later stamps snap. Reject with explicit code (illustrative: `BOUNDS_ROLL_INDETERMINATE_LOCAL`) + diagnostic naming which field (due vs which bound) and gap vs fold. No inverted bounds after a successful roll. (`recurrence.py` / `next_due_at` have **no** gap/fold policy today — do not invent a third policy.)
4. This roll is **recovery-path only** — do **not** silently change today’s `complete_task` / `next_due_at` in this unlock family.
5. **Stable authorize instant (completion-anchored):** Bind the operator-reviewed **authorize instant** (the wall-clock / zone instant used as the completion-anchored anchor at review) into the authorize request alongside successor choice, catch-up dates, and series target bounds. At commit, completion-anchored recomputation **MUST** use that **bound** instant — **MUST NOT** silently substitute a later `now` that shifts the reviewed next-normal target.
6. **Concurrency / revision binding:** Under `lock_owner_scheduling` + `assert_scheduling_revision`:
   - Bind operator-reviewed successor choice (accept past / step count N / abort), **authorize instant**, catch-up dates, and series target bounds to the **current** `expected_revision` at authorize.
   - Revalidate successor computation + gates under the lock after refresh (`populate_existing`); if rule/bounds/revision drifted → conflict/reject, **no** partial writes. Successor must still equal the reviewed target under the bound authorize instant.
   - Separate-session competing recover vs recover; recover vs release/skip; recover vs late-injected rollback/stale rev → **409** / nested savepoint rollback / idempotent replay as applicable (see A5/A6 concurrency cases).

### C5 — Multi-week behavior and exact operator choices

| Rule kind | Next-normal target | If landing still past “now” | Catch-ups for skipped intermediate slots |
| --- | --- | --- | --- |
| **Fixed** | First instant strictly after **missed due** | **Explicit operator review** required before commit (accept past next-normal dates **or** step further / abort). No silent auto-loop | **None** — one catch-up for the held miss only; no multi-miss fan-out |
| **Completion-anchored** | First instant strictly after **bound authorize instant** in rule zone | By construction future (or equal-policy: strictly after); if still unusable under **series gate** → reject | **None** — intermediates skipped (authorize-as-anchor) |

Operator review choices when fixed next-normal is past (must be named in API/UI later; contract-level):

1. **Accept past landing** — commit recovery with that next-normal `due_at` + rolled bounds **with explicit acknowledgement**. Series gate: structural/geometry only — **do not** apply future-time still-past release checks to the series (see §C-gate). Accept-past **does not** promise placeable next-normal at authorize; subsequent calculate/preview may re-hold the past landing (intentional visibility — see §C-gate “visible honesty”).
2. **Step further** — advance one additional fixed step (or N reviewed steps) until accepted / future; still **one** catch-up for the original held episode. Past landing not committed without accept. Stepped-to-future commits run the **full temporal** series gate (§C-gate branch 3).
3. **Abort** — no writes (txn rollback).

### C6 — Atomic recovery + series changes

Under `lock_owner_scheduling` + `assert_scheduling_revision(expected_revision)`, in **one** nested savepoint / txn:

1. Load **named** `disposition_id` + owner + task; require `unresolved_held` and a **recurring** task (else reject — one-offs use release).
2. Snapshot miss-era progress onto disposition (§C1) — including explicit progress-entry id-set and persisted disjoint membership assignment.
3. Fail-closed on conflicting series blocks via conservative predicate (§C2) before mutating identities.
4. Create catch-up one-off Task (link to miss episode / `episode_key`); init effort per §2.2 (remaining default = last confirmed remaining; operator-reviewed override allowed in-request).
5. Apply catch-up usable dates; run **catch-up gate** (§C-gate Catch-up).
6. Advance series `due_at` via non-`complete_task` helper + bounds/deadline roll (§C4, including due gap/fold); run **series gate** (§C-gate Series) for the committed branch; reset live series effort (§2.2).
7. Terminalize disposition (illustrative resolution `recovered`); append recovery event; **one** `increment_scheduling_revision`.
8. On any gate/validation failure: **rollback all** of the above — no half-written catch-up, no half-reset series, no resolution change, no rev bump.

### C7 — Named-episode idempotency

| Request | Current state | Result |
| --- | --- | --- |
| recover | already recovered **same** `disposition_id` | **200 idempotent** — return existing catch-up link; **no** second Task; **no** second rev bump; **no** second event required |
| recover | `released` or `skipped` | **409** `CONFLICT_TERMINAL` |
| recover | wrong/missing `disposition_id` | **404** |
| recover | second authorize for same episode after success | Idempotent same identity — **never** invent a second catch-up without explicit re-auth product (out of min scope: no re-auth) |

Identity: **`disposition_id` + owner_id + task_id`** only — never “latest held for task.”

### C8 — Stale / conflicting state

1. Stale `expected_revision` → **409** revision conflict — **precedes** terminal no-op (parity with release).
2. Cross-terminal conflict → **409** `CONFLICT_TERMINAL`.
3. Non-recurring task → reject (use release).
4. Skipped task / skipped disposition → reject recovery (post-skip reactivation is **out of scope**).
5. Concurrent drift under owner lock: refresh named row; do not clear a newer episode via an old id. Revalidate successor + gates after refresh (§C4.5–C4.6).

### C9 — Scheduling revision / fingerprint effects

1. Successful recovery → **exactly one** `scheduling_revision` bump for the authorize (not per sub-write).
2. Fingerprint-relevant mutations in that same commit: disposition resolution change; series `due_at` + bounds/deadline; series worked/remaining; new catch-up task fields hashed by fingerprint v4. Apply must see **one** coherent stale signal — not multiple conflicting mid-flight revisions.
3. Idempotent replay → **no** further bump / fingerprint churn.
4. Recovery **must not** write dispositions inside `calculate()`.

### C-gate — Usable-dates: Catch-up gate vs Series gate

#### Catch-up gate (always)

Catch-up **MUST always** run the full release usable-dates gate (`_assert_usable_dates_for_release` parity): `unsupported_shape` · `geometry_infeasible` · `latest < now` · `start_floor > latest` (i.e. `max(now, earliest) > effective_latest_start`). Reject **`BOUNDS_STILL_MISSED`** + nested savepoint rolls everything back. Effort via `placement_effort_minutes` on the **catch-up**. Catch-up **never** gets an accept-past exception. **Not** a free-slot / horizon promise.

#### Series gate (after roll)

1. **Always:** structural/geometry validation (`unsupported_shape`, `geometry_infeasible`) on rolled bounds+effort — reject inverted/infeasible. (When all bounds are null, structural still applies to the due/effort shape the gate defines; temporal checks below still apply to due/effective floors as release does.)
2. **Accept-past branch (C5 choice 1 only):** If next-normal landing is still past operator now **AND** operator chose Accept past: do **NOT** apply the two future-time / still-past release checks (`latest < now`, `start_floor > latest`) to the series. Commit requires the **explicit acknowledgement** already named in C5 choice 1. Structural/geometry still required.
3. **Non-accept-past / future-target branch (explicit):** If the committed next-normal is a **future** (or otherwise non-accept-past) target — including fixed stepped-to-future and completion-anchored future due — the series gate **MUST** run the **full** temporal release checks (`latest < now`, `start_floor > latest`) in addition to structural/geometry. Accept-past exemption **does not** apply. Example: future `due_at` with already-expired rolled `latest` / `deadline` → reject (`BOUNDS_STILL_MISSED` or equiv.); no commit.
4. **If operator did not accept past** and landing is still past: past landing is **not** committed; blocked (A7).

#### Visible honesty — what next calculate does with accepted-past series occurrence (Tesla code truth)

- Recovery does **not** write dispositions inside calculate.
- After hold terminalized, calculate no longer skips via `unresolved_held` for that task.
- With past rolled bounds: `evaluate_occurrence_bounds` → typically `occurrence_bounds_miss` (`latest < now`) → skip placement; next preview `stage_auto_misses` may record a **new** `unresolved_held` under the **new** `episode_key` (bounds+deadline digest) — this is a **new hold for the past next-normal window**, **NOT** a second catch-up Task, **NOT** silent stack into recovery, **NOT** hiding the hold.
- If miss-era blocks/pins/worked remain: `in_flight_hold_trigger` may fire instead (see §C2) — suppress new placement.
- **Contract statement:** accept-past does **not** promise placeable next-normal at authorize time; operator may immediately see need-decision again for the past landing — that is **intentional visibility**, not a bug to paper over inside recovery.

### C-out — Explicit non-features inside this contract

- No auto backlog insert.
- No silent stack of catch-up into next-normal or undeclared parallel holds.
- No multi-miss catch-up fan-out.
- No change to `complete_task` effort/bounds behavior in this slice.
- No post-skip reactivation path.
- No silent snap of indeterminate local times on recovery due/bounds roll (fail-closed).
- No silent re-key / delete / unpin of miss-era blocks inside authorize; **no** delete/unpin-history workaround to pass C2.
- **EXCEEDS_SLICE / deferred:** occurrence-keyed block isolation / reader filters so historical blocks remain evidence while next-normal places (§C2.4).
- No broad historical-correction UX beyond the smallest ledger-only API (§C1.3).
