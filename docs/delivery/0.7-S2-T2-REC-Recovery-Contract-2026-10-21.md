## 2. Locked product semantics (encode exactly)

These are **pinned** by Trish via Dex **`1792625085.114399`**. Engineering must implement them verbatim; overrides require a new Trish/Dex stamp.

### 2.1 Scope

- **Recurring-only** reviewed recovery.
- Authors a **distinct catch-up one-off** beside **next-normal** on the live series task.
- Series advancement **must not** falsely complete missed work (must **not** call `complete_task` on the miss).
- Completing the catch-up one-off **must not** advance the series.

### 2.2 Progress / logged work (quantitative pin: 60 / 25 → remaining 35)

| Identity | Live `worked_minutes` | Live `remaining_minutes` | History |
| --- | --- | --- | --- |
| Miss episode (historical) | n/a | n/a | Disposition + immutable `bounds_snapshot` + `episode_key`; **snapshot** miss-era worked total (= **25**) + progress-entry ids **before** live reset; append-only `task_progress_entries` **remain** on series `task_id` |
| Catch-up one-off (new Task) | **0** at create | **Default = last confirmed remaining** (**35** in example), **adjustable by Trish during review** — not automatic full restart to **60** | Fresh ledger only after create; **does not** receive the historical 25 |
| Series next-normal (same Task, advanced) | **0** after reset | **`estimated_duration_minutes`** (full estimate, **60** in example) | Same historical ledger rows retained; miss-era 25 **must not** remain as live worked |

**Never:** duplicate logged minutes onto both live identities; leave series live at 25/35 after advance; delete/move series ledger rows onto the catch-up.

### 2.3 Cadence

- **Completion-anchored** (`is_fixed=false`): recovery **authorization time** (operator authorize / `now` in rule zone) is the **anchor** for the next occurrence — first RRULE instant strictly after authorize, matching today’s completion-anchored skip-of-intermediate-slots.
- **Fixed** (`is_fixed=true`): retain cadence — first RRULE instant strictly after the **missed occurrence’s due** (same step-from-previous_due as today’s fixed `next_due_at`). If the proposed next-normal instant is **still in the past** relative to operator now → **explicit operator review** (accept past landing, step further, or PATCH) — **no** silent auto-loop to “next future” inside recovery.

### 2.4 What recovery is not

- Ordinary **one-off** same-task retries continue to use **`release_held`** (date-first / atomic bounds). Recovery adds nothing.
- **Post-skip reactivation** stays a **separate later** semantic question — not this contract’s feature, not folded into recovery authorize.

### 2.5 Operator / stacking invariants

- **Usable-dates gate parity with release** on catch-up dates (temporal only — not free-slot / horizon).
- **No automatic backlog.**
- **No silent stack** into tomorrow / next-normal / parallel undeclared holds.
- **D3 is NOT closed** by this product lock or by ACCEPT of this contract alone.
- **No coding unlock** from this packet alone — Dex ACCEPT of contract + later explicit coding unlock required.

## 3. Engineering contract clauses

Recovery is a **dedicated path** (name illustrative: `recover_held` / authorize-recovery). It is **not** `complete_task`, **not** `release_held`, **not** a calculate side effect.

### C1 — Progress-ledger / correction attribution after live reset

1. **Before** mutating live series effort columns: snapshot onto the miss disposition (or linked immutable record) at least: miss-era `worked_minutes`, `remaining_minutes`, `estimated_duration_minutes`, and the set of `task_progress_entries.id` attributable to the miss era (by timestamp / explicit list).
2. Leave all existing `task_progress_entries` rows on the **series `task_id`**. Do **not** rewrite, delete, or re-key them to the catch-up.
3. After live reset, **corrections** targeting miss-era entries remain valid under `task_progress_entries_correction_same_task` (same series `task_id` + owner). Corrections must **not** orphan, double-attribute across catch-up + series, or require inventing an `episode_key` on the ledger.
4. New progress on catch-up posts only to the catch-up `task_id`. New progress on next-normal posts only to the series `task_id` after reset.

### C2 — Preserved old blocks

1. Existing `ScheduledBlock` rows tied to the miss-era occurrence on the series task are **not** silently reused as next-normal placement and are **not** reassigned to the catch-up without an explicit, tested rule.
2. Default recovery policy: **do not mutate** miss-era blocks’ task identity; they remain historical evidence on the series task (pinned or unpinned as already stored). Catch-up and next-normal obtain placement only via ordinary calculate/place **after** recovery clears the hold — not by rewriting old block rows into new identities.
3. Fail closed if an implementation would leave two live identities competing for the same pinned block without an explicit operator-visible disposition.

### C3 — Recurrence end / no successor

1. If `next_due_at` (or equivalent helper with the correct anchor) returns **`None`** (series exhausted / past `ends_on` / no in-frame successor): **fail closed** — no invented occurrence, no silent one-off-only “series” advance, no half-created catch-up without an explicit operator path.
2. Operator path when no successor: reject recovery authorize with an explicit code (illustrative: `RECURRENCE_NO_SUCCESSOR`); disposition stays unresolved_held unless operator chooses leave/skip/release separately.

### C4 — Source-zone bounds / deadline roll including DST

1. On successful series advance, roll `start_no_earlier_at` / `start_no_later_at` / `deadline_at` (and soft target if present) by the **same calendar delta** as `due_at` advanced, computed in **`RecurrenceRule.timezone`**, then store UTC.
2. Preserve local clock-of-day and wall-date offset relative to the new due. Null fields stay null.
3. **DST:** roll must survive spring-forward / fall-back without inverted bounds or unintended ±1h wall-clock shift relative to the rule zone. Fail closed on inverted bounds after roll.
4. This roll is **recovery-path only** — do **not** silently change today’s `complete_task` in this unlock family.

### C5 — Multi-week behavior and exact operator choices

| Rule kind | Next-normal target | If landing still past “now” | Catch-ups for skipped intermediate slots |
| --- | --- | --- | --- |
| **Fixed** | First instant strictly after **missed due** | **Explicit operator review** required before commit (accept past next-normal dates **or** step further / PATCH). No silent auto-loop | **None** — one catch-up for the held miss only; no multi-miss fan-out |
| **Completion-anchored** | First instant strictly after **recovery authorization time** in rule zone | By construction future (or equal-policy: strictly after); if still unusable under gate → reject | **None** — intermediates skipped (authorize-as-anchor) |

Operator review choices when fixed next-normal is past (must be named in API/UI later; contract-level):

1. **Accept past landing** — commit recovery with that next-normal `due_at` + rolled bounds (operator acknowledges).
2. **Step further** — advance one additional fixed step (or N reviewed steps) until accepted / future; still **one** catch-up for the original held episode.
3. **Abort** — no writes (txn rollback).

### C6 — Atomic recovery + series changes

Under `lock_owner_scheduling` + `assert_scheduling_revision(expected_revision)`, in **one** nested savepoint / txn:

1. Load **named** `disposition_id` + owner + task; require `unresolved_held` and a **recurring** task (else reject — one-offs use release).
2. Snapshot miss-era progress onto disposition (§C1).
3. Create catch-up one-off Task (link to miss episode / `episode_key`); init effort per §2.2 (remaining default = last confirmed remaining; operator-reviewed override allowed in-request).
4. Apply catch-up usable dates; run **usable-dates gate parity with release** (§C-gate).
5. Advance series `due_at` via non-`complete_task` helper + bounds/deadline roll (§C4); reset live series effort (§2.2).
6. Terminalize disposition (illustrative resolution `recovered`); append recovery event; **one** `increment_scheduling_revision`.
7. On any gate/validation failure: **rollback all** of the above — no half-written catch-up, no half-reset series, no resolution change, no rev bump.

### C7 — Named-episode idempotency

| Request | Current state | Result |
| --- | --- | --- |
| recover | already recovered **same** `disposition_id` | **200 idempotent** — return existing catch-up link; **no** second Task; **no** second rev bump; **no** second event required |
| recover | `released` or `skipped` | **409** `CONFLICT_TERMINAL` |
| recover | wrong/missing `disposition_id` | **404** |
| recover | second authorize for same episode after success | Idempotent same identity — **never** invent a second catch-up without explicit re-auth product (out of min scope: no re-auth) |

Identity: **`disposition_id` + owner_id + task_id`** only — never “latest held for task.”

### C8 — Stale / conflicting state

1. Stale `expected_revision` → **409** revision conflict — **precedes** terminal no-op (parity with release).
2. Cross-terminal conflict → **409** `CONFLICT_TERMINAL`.
3. Non-recurring task → reject (use release).
4. Skipped task / skipped disposition → reject recovery (post-skip reactivation is **out of scope**).
5. Concurrent drift under owner lock: refresh named row; do not clear a newer episode via an old id.

### C9 — Scheduling revision / fingerprint effects

1. Successful recovery → **exactly one** `scheduling_revision` bump for the authorize (not per sub-write).
2. Fingerprint-relevant mutations in that same commit: disposition resolution change; series `due_at` + bounds/deadline; series worked/remaining; new catch-up task fields hashed by fingerprint v4. Apply must see **one** coherent stale signal — not multiple conflicting mid-flight revisions.
3. Idempotent replay → **no** further bump / fingerprint churn.
4. Recovery **must not** write dispositions inside `calculate()`.

### C-gate — Usable-dates parity with release

Reuse the same temporal checks as `_assert_usable_dates_for_release`: `unsupported_shape` · `geometry_infeasible` · `latest < now` · `max(now, earliest) > effective_latest_start`, effort via `placement_effort_minutes` on the **catch-up** (and on series next-normal bounds after roll where validated). Reject **`BOUNDS_STILL_MISSED`**; nested savepoint rolls everything back. **Not** a free-slot / horizon promise.

### C-out — Explicit non-features inside this contract

- No auto backlog insert.
- No silent stack of catch-up into next-normal or undeclared parallel holds.
- No multi-miss catch-up fan-out.
- No change to `complete_task` effort/bounds behavior in this slice.
- No post-skip reactivation path.
