## 2. IN / OUT — S2 first vertical vs full S2

### 2.1 Recommended first vertical (S2-V1) — unlock chunking writes safely

**Goal:** Smallest shippable that flips `CHUNKING_CUTOVER_PENDING` → allowed without lying about placement or fingerprints.

| IN (S2-V1) | Expectation |
| --- | --- |
| **Effective-bounds resolver** | Inherit (NULL) / explicit minutes / No limit (`max_block_unbounded`) / `keep_in_one_block` resolved once for placer, fingerprint snapshot, and outcomes/explanations. Conflict → correction error (SPEC §5.1). |
| **Placer uses resolved bounds** | Keep-in-one = all **remaining** in one continuous eligible window. Final remainder &lt; min stays legal. Buffers ≠ work duration. |
| **Allow previously rejected writes** | Task/settings paths that today return `CHUNKING_CUTOVER_PENDING` accept inherit / No limit / keep-in-one when all readers above are live. |
| **Activation side effects** | Bump `scheduling_revision` on cutover activation (S0 §0.1). Start fingerprint **v4** at least for `duration` (original/worked/remaining + inherit vs explicit vs No limit + keep-in-one). Existing v3 rows → `provenance`. Do **not** rewrite historical explanation JSON. |
| **API / effective read honesty** | Effective chunking is scheduling-effective once writes land; stop “preview only / pending cutover” copy for those fields. |
| **Regression shield** | Explicit numeric min/max behavior unchanged for seeded tasks; reject path tests inverted to accept path + placer/fingerprint coverage. |

| OUT of S2-V1 (defer to later S2 slices or other trains) | Why |
| --- | --- |
| Future-tail pin reservation (§2) | Separate vertical (S2-V2); S1 remaining read shim stays until then |
| Working as SoT / stop `workweek_*` mirror | S2-V3 |
| Unclassified → General eligibility | S2-V3 |
| May/Must/Prefer in placer | S2-V4 |
| Full fingerprint `availability` / `context` categories | Can land with V3/V4; not required to unlock bounds writes if `duration` v4 is honest |
| SS-30 execution evidence | S2-V6 (policy already approved) |
| OPT-CONVERT / map conversion apply | Later; legacy maps stay live |
| Context timeline / travel matrix | SPEC deferred pieces stay deferred |
| Settings About / UI tabs | **S3** |
| Config propose/apply as product surface | May stub for conversion later; not V1 |

**Why this order:** S0 §0.1 is an **atomic activation point** for chunking writes. Unlocking writes before placer + fingerprint + outcomes resolve inherit/No-limit/keep-in-one reintroduces the `int(raw)` footgun. Pin reservation and eligibility cutover are larger behavioral shifts and can ship behind V1 without blocking bound persistence.
