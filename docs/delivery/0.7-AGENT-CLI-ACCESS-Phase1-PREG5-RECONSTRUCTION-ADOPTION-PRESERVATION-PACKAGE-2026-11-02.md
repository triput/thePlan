### 3.3 Sidecars (per tar)

For each `.tar`, write sibling files:

| Sidecar | Content |
| --- | --- |
| **`.sha256`** | SHA256 **of the tar file** (e.g. `Get-FileHash -Algorithm SHA256`) |
| **`.meta.json`** | JSON object with at minimum: **`digest`** (field name retained — value is the reconstruction **image ID** `sha256:…`), **`source_tag`**, **`stamp`** (`20261102T055454Z-b349fb02`), **`taken_utc`**, **`not_original_digest`**: `true`, **`historical_source_digest`** (role-specific hex **without** `sha256:` prefix — API tar → `9aac7395a068d0761ad81c2339d60b69f5bd90e0cb7ef498f26d2634b0edfa36`; web tar → `bff14006fb87757ce5c5ce28be24223195a01e4154de0d437430dfaa3f89c928`), optional **`historical_source_digests`** array for cross-reference only, **`reconstruction`**: `container_fs_export_import` |

**Terminology:** Use **image ID** consistently for Docker content identity (`sha256:` + 64 hex = Config digest). Sidecar **`.meta.json`** may still label the field **`digest`**; treat it as **image ID**, not tar file hash.
