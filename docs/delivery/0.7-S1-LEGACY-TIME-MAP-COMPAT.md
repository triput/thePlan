- Map selection: task → project → epic replacement — [`windows.py`](../../apps/api/app/scheduler/windows.py) `effective_preferred_time_window_id`.
- Workdays are Monday-first **count**, not a mask: `day.weekday() < workweek_days` (`is_workday`). Bands use a separate weekday **bitmask** (`1 << weekday()`, Monday = bit 0) and are clipped to `[workday_start_local, start + workday_minutes)`.
- Non-strict search order on **every** workday, including days that already have green/yellow: green clips, then yellow clips, then neutral = the whole workday minus red. Neutral is not limited to unbanded weekdays and is not the complement of green/yellow.
- Strict: green/yellow only. Red subtracts from green, yellow, and (non-strict) neutral. `_map_block_reason` returns `red_exclusion` only when no allowed clip remains.
- Overrides replace that day’s bands + strictness — [`time_map_overrides.py`](../../apps/api/app/scheduler/time_map_overrides.py) `effective_day_map`. Date match uses the override’s stored IANA zone.

## 3. Master matrix — legacy state → bridge → conversion

**Legend — operator action**

| Code | Meaning |
| --- | --- |
| **—** | No action; preserve automatically |
| **OPT-CONVERT** | Named kind on `POST /scheduling/config/propose` + `apply` (Q1). Never at `028` seed. No second focus-window convert route |
| **OPT-CLEAR** | Clear `preferred_time_window_id` at stated scope to restore inheritance (distinct from “permit no time”) |
| **OPT-REPLACE** | User replaces map assignment or bands via existing `/focus-windows` + assign APIs |
| **BLOCK** | Reject or config-only until S2; do not reinterpret |

### 3.1 Assignment and inheritance

| Legacy state | Preserve behavior (S1 bridge) | Opt-in conversion target (S2+ model) | Operator action | Notes |
| --- | --- | --- | --- | --- |
| No map on task, project, or epic | Eligible within global workday on workdays only | Task scheduling: **General** purpose link (no copied windows) | **—** until S2 cutover; then automatic **link only**, not hour copy | S0 §4: seed General = today’s window so SS-01 holds at cutover |
| Map on **epic** only | Project/task inherit epic map id | **May:** attach converted availability rule set at epic scope with visible origin | **OPT-CONVERT** per map | Replacement inheritance, not additive with project map |
| Map on **project** (task unset) | Task uses project map | Same at project scope | **OPT-CONVERT** | SS-09 |
| Map on **task** | Task map wins | Same at task scope | **OPT-CONVERT** | Clearing task map → **OPT-CLEAR** restores project/epic chain |
| Task + project both set | Task wins; project map ignored for that task | Convert task assignment; project map remains for other tasks | **OPT-CONVERT** at task scope | No merge of two maps |
| Cleared local assignment (NULL id) | Inheritance restored | N/A | **OPT-CLEAR** | **Not** the same as “only allow Sunday night” empty requirement (SS-10) |

**Implementation note:** Do **not** store General/unclassified purpose in `preferred_time_window_id` (S0 §7).

### 3.2 Strict vs non-strict maps

| Legacy state | Preserve behavior (S1 bridge) | Opt-in conversion target | Operator action | Notes |
| --- | --- | --- | --- | --- |
| **Non-strict** map with green/yellow bands on selected weekdays | On **every** workday: search green, then yellow, then neutral = entire workday minus red. Neutral is appended even when that weekday already has green/yellow. It overlaps those clips; it is not “unbanded days only” | Eligible set stays green ∪ yellow ∪ (workday − red). **Prefer** ranks green before yellow. Dropping same-day neutral (rest of the workday) is a **narrowing** the operator must see in the interval diff — not S1 behavior | **OPT-CONVERT** template **non-strict → eligible union + Prefer rank** | SPEC §3’s “on unbanded days” sentence is true and incomplete. Code also fills neutral on banded workdays. A Saturday bit does nothing when that day fails `is_workday` |
| **Strict** map with green/yellow bands | Only green/yellow clips on workdays whose bitmask hits; **no** neutral on any workday | **Only allow selected days/times** for the band pattern; or **Change selected days** when replacing an inherited window on a subset | **OPT-CONVERT** template **strict → exclusive requirement** | Deadline/priority does not weaken strict (no such branch in `placement.py`) |
| Strict map, weekday with **no** band bit | No clip. `_map_block_reason` → `no_time_map_interval` (not `red_exclusion`) | Same — no placement unless a scoped exception | **—** or scoped exception (S2) | No ancestor fall-through (SPEC §4.3) |
| Non-strict, zero bands | Neutral = full workday (no red to subtract) | **May** = full Working window, or an operator-defined slice | **OPT-CONVERT** or **OPT-REPLACE** bands | Distinct from strict empty (below) |

| Non-strict: red eats green/yellow but not the whole workday | Neutral remainder is still eligible. Reason is **not** `red_exclusion` | Exclusions + the remaining May window | **OPT-CONVERT** | `red_exclusion` on a non-strict day only when red also empties neutral (red covers the workday) |
| Red on non-strict with no green/yellow | Neutral minus red still applies | Exclusions + May windows | **OPT-CONVERT** | |

### 3.7 Toward May / Must / Prefer (explicit conversion templates)

Recommended **OPT-CONVERT** rows (product semantics from Dex §8 / SPEC §4.2). Implementation may batch these in a proposal; operator must approve.

| Legacy pattern | Recommended conversion | Strength in new model |
| --- | --- | --- |
| Non-strict map, green/yellow bands | Eligible hours = green ∪ yellow ∪ (workday − red), matching today’s search. **Prefer** ranks green, then yellow. Same-day neutral (the rest of the workday) stays unless the operator’s template drops it and the receipt shows the lost intervals | May (eligible union) + Prefer rank |
| Strict map, same bands | **Only allow** the green ∪ yellow clips. No neutral | Must (exclusive) |
| Map + implicit “home” need (not in legacy data) | **Must** context/home only if the operator confirms. Do not infer from the map name | Must — context layer S2+ |

| Yellow tier | Yellow is eligible time, searched after green. Map it into the eligible union and rank it under green. Prefer-only with no eligible window **drops** those hours (Dex: Prefer does not create availability) | Prefer rank inside the eligible set |
| Single shared map on many assignments | One converted rule set; **retire** the map with a replacement preview (SPEC §4.2). Do not flip the `focus_windows` row while any unconverted FK still points at it | Atomic migrate of the assignments in the proposal |
| Operator wants to **drop** legacy neutral | Exclusive bands and no May fallback, chosen in the proposal | Operator chooses the strict template |

**Not in S1:** Default auto-conversion at migrate. **Not in S1:** Opt maps into May/Must stack in placer without **OPT-CONVERT** apply.

## 5. Day-scoped ops vs legacy maps (SS-10)

Until conversion, legacy maps **do not** expose the new UI verbs; behavior stays column B. After **OPT-CONVERT**, map to column C.

| Approved operation (SPEC §4.3) | Legacy map analogue (bridge) | After conversion |
| --- | --- | --- |
| **Change selected days** | Edit bands / override for subset of weekdays; replacement on those days only | Dated or recurring **replace** on target policy window |
| **Only allow selected days/times** | **Strict** map with bands only on those days (no neutral elsewhere) | Must-style exclusive window |
| One-date change expires | **Temporary override** for single local date range | Dated replacement row with expiry |
| Empty required availability | Strict map with no bands **or** strict empty override | Must with zero windows — no fall-through |
| Clear assignment | NULL `preferred_time_window_id` | Restore inheritance / General link at S2 |

**Acceptance:** SS-09 (inheritance preserved on migrate), SS-10 (strict/non-strict, empty vs cleared, Sunday-night-style exclusive).
