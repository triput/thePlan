## 6. Failure handling

| Failure class | Action |
| --- | --- |
| Preflight / approval / dump SHA / sidecar / port collision | **Refuse** — not owned; **no** `down -v` |
| **`pg_restore` partial or non-zero** | Fail — capture restore outcome artifact; if owned, **`Capture-DisposableFailureDiagnostics`**, attempt cleanup once, **`failure.receipt.json`**, **no** success receipt |
| **Alembic ≠ 042** or **`agent_credentials` present** | Immediate fail — treat as wrong dump era or corrupt restore; same cleanup discipline |
| **Inventory count mismatch** (≠ 2 / 590 / settings 2) or empty ID aggregates | Immediate fail — **`inventory-observations.json`** still written when SQL succeeded; failure receipt references authority |
| **HTTP mismatch** (SETUP_REQUIRED, non-401, title miss, proxied hop differs) | Immediate fail — partial **`http-endpoint-observations.json`**; structured throw preserved |
| **Transport-not-ready** at deadline | Fail with last **`transport_fail`** observation (val-4 policy) |
| **Cleanup incomplete / uncertain** | Nonzero exit; **`cleanup-outcome.final.json`**; **`failure.receipt.json`**; **no** `validation.receipt.json`; **no** second cleanup pass |
| **Running image ≠ pin** | Abort before HTTP — same as val-4 |
